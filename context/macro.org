[OBS id:obs.context.macro.syntax-convention src:macro.h:7 conf:high]
  Macros are ordinary =define= forms whose lambda declares =-> Syntax= as
  the return type.  The expander registers them by scanning all top-level
  defines before the main expansion pass.  Examples:
  =(define (when condition . body -> Syntax) (if condition (begin . body) (begin)))=
  =(define (swap! a b -> Syntax) (let [tmp a] (set! a b) (set! b tmp)))=

  type in the surface system)

[OBS id:obs.context.macro.quasi-output src:macro.h:45 conf:high]
  If the macro body contains =#(...)= the expander strips the marker and
  only the inner subtree becomes the macro output.  If no =#(...)= appears,
  the entire body is the output template.  Example:
  =(define (assert condition message -> Syntax)
    (if debug-mode
      #(when (not condition) (error message))
      #(begin)))=

[FIX id:fix.context.macro.quasi-output-eval date:2026-07-27 by:codex supersedes:think.context.macro.quasi-output-eval]
  Supported forms outside =#()= execute in the deterministic Syntax evaluator.
  Boolean conditionals select one branch at expansion time; syntax constructors
  build the returned tree explicitly. The remaining work is to expand the
  evaluator kernel and lexical-context API, not to introduce evaluation itself.

[OBS id:obs.context.macro.hygiene src:macro.h:36 conf:high]
  Names introduced inside a macro body (lambda params, =let= bindings, inner
  =define=s) that are NOT pattern variables are renamed to the pattern:
  =macroname__varname__N=, where N is a global monotonic counter.  Pattern
  variables and free references to outer definitions pass through unchanged.
  This prevents unintentional capture between macro-generated code and the
  surrounding scope.

[THINK id:think.context.macro.hygiene-counter date:2026-06-13 by:codex]
  The global counter N ensures uniqueness across all macro invocations
  within a single compilation unit.  The separator =__= (double underscore)
  is reserved by the compiler and cannot appear in user-written identifiers.
  On reset between units, =macro_clear()= resets the counter.

[OBS id:obs.context.macro.variadic-splicing src:macro.h:53 conf:high]
  A rest parameter (=is_rest=) captures zero or more trailing arguments.  In
  the template, if the rest name appears as a list element the captured nodes
  are *spliced* (inserted flat into the enclosing list).  In non-list position
  a single-element rest wraps the captured nodes in =(begin ...)=.

[THINK id:think.context.macro.rest-splicing-edge src:macro.h:55 conf:high]
  Splicing semantics: =(my-and . rest)= → =(if x (my-and . rest) False)=
  where =rest= splatted into the =if= tail produces N-ary chaining.
  Single-element capture in non-list position (e.g. =(list . rest)= with one
  arg) wraps in =(begin captured)= to preserve the single expression.

[OBS id:obs.context.macro.fixpoint src:macro.h:32 conf:high]
  After the initial registration pass, =macro_expand_all= walks every
  remaining AST, expands macro call sites, and repeats the walk to a
  fixpoint capped at 1 024 rounds.  This ensures macros that expand into
  other macro calls are fully resolved.  If the cap is reached the
  expansion is aborted (the compiler reports an error or returns the
  partially-expanded result).

[OBS id:obs.context.macro.func-expand-all src:macro.h:78 conf:high]
  =macro_expand_all(exprs, count)= — Entry point.  Takes a flat list of
  top-level ASTs from =parse_all= / =wisp_parse_all=.  Pipeline:
  1. Scan for defines whose lambda has =return_type= ="Syntax"= → register
     as macros and remove from the output (macros are compile-time only).
  2. Walk every remaining AST calling =macro_try_expand= at each list node.
  3. Repeat step 2 to fixpoint (capped at 1024 rounds).  Returns a new
     =ASTList=.  Caller owns the returned exprs array; individual AST nodes
     are live.  Macro define nodes consumed in step 1 are freed internally.

[THINK id:think.context.macro.expand-ownership date:2026-06-13 by:codex]
  The returned =ASTList= contains live AST nodes that are either original
  (non-macro) or freshly allocated for the macro output.  The caller must
  =free()= the array but must not free individual AST nodes that belong to
  the original input.  A flag or side table distinguishes owned vs borrowed
  nodes if needed.

[THINK id:think.context.macro.pattern-variables date:2026-06-13 by:codex]
  Pattern variables are the formal parameters of the macro lambda.  During
  expansion, actual arguments are substituted for pattern variables in the
  template.  Non-pattern variables (let bindings, inner lambdas) are
  hygienically renamed.  The current implementation does not support
  ellipsis ... patterns (Scheme-style) — variadic behaviour is via a single
  rest parameter.

[THINK id:think.context.macro.expansion-order date:2026-06-13 by:codex]
  Expansion is outermost-first: the expander walks the AST top-down and
  expands the outer list first, then recurses into the result.  This means
  a macro that produces another macro call will have that call expanded
  in a subsequent fixpoint round, not inline during the same walk.

[DOC id:doc.macro.category-contract src:context/macro.org conf:high]
  This section declares the category contract for =macro=. It is the
  routing target for failures and future test/context links touching macro
  registration, pattern matching, template expansion, and the fixpoint
  expansion loop.

#+CAPTION: Macro System Category Contract
| Field | Contract |
|-------+----------|
| Owned phase | Macro registration (macro_register), pattern matching and template substitution, fixpoint expansion loop (macro_expand_all), Syntax type detection for macro-producing macros. |
| Inputs | AST with define-macro forms and macro call sites, macro registry populated during parsing. |
| Outputs | Expanded AST with no remaining macro calls, hygienically renamed non-pattern variables, fixpoint convergence signal. |
| Invariants | Expansion terminates (fixpoint bound enforced); pattern variables are substituted, non-pattern variables are hygienically renamed; Syntax-typed macros return AST nodes, not runtime values; expansion is outermost-first. |
| Test hooks | Macro expansion test fixtures, fixpoint convergence tests, hygiene tests, Syntax type round-trip tests. |
| Failure symptoms | Non-terminating expansion (fixpoint bound hit), pattern variable mismatch, hygiene violation (variable capture), Syntax type detection failure, macro-not-found errors. |
| Context neighbors | reader, codegen-ops, language, env, wisp |

[DEC id:dec.macro.category-contract-owner date:2026-06-18 by:big-pickle]
  Failures matching the symptoms above should start triage in this category, then
  follow the listed neighbors only when the local contract does not explain the
  issue.

* Procedural Syntax Evaluation

[FIX id:fix.macro.syntax-evaluator-kernel-2026-07-27 src:macro.c,tests/test_how_to_examples.py conf:high]
  Syntax-returning Monad functions pass their substituted tree through a
  deterministic compile-time evaluator. It executes Boolean conditionals,
  sequencing, numeric arithmetic and comparisons, and reader-lowered lexical
  bindings. Calls outside the evaluator kernel remain syntax constructors, so
  object-language applications are not accidentally executed by the compiler.

[OBS id:obs.macro.immutable-syntax-constructors-2026-07-27 src:macro.c,how_to/ReaderSyntax.mon conf:high]
  =syntax-list=, =syntax-symbol=, =syntax-string=, and =syntax-number= construct
  fresh owned AST values during expansion. The Reader DSL tutorial uses these
  primitives to build an application procedurally from Monad code.

[FIX id:fix.macro.syntax-evaluator-diagnostics-2026-07-27 src:macro.c,tests/test_how_to_examples.py conf:high]
  Compile-time type errors from syntax primitives include the active source
  filename and source coordinates. Evaluation is capped by a deterministic
  step budget so malformed transformers cannot consume unbounded compiler work.

[FIX id:fix.macro.structural-syntax-api-2026-07-27 src:macro.c,tests/test_how_to_examples.py conf:high]
  Syntax transformers can inspect number, string, symbol, and list shapes;
  measure and index syntax lists; extract symbol text; and compare compile-time
  strings. Indexing validates integral bounds and reports a source-located
  diagnostic instead of exposing an AST address.

[FIX id:fix.macro.compile-time-helper-calls-2026-07-27 src:macro.c,tests/test_how_to_examples.py conf:high]
  A Syntax-returning function may call another Syntax-returning function during
  evaluation. Helper calls reuse parameter binding, hygienic introduced-name
  collection, the caller's evaluation budget, and deterministic evaluation;
  they do not emit runtime functions.

[OBS id:obs.macro.expansion-json-trace-2026-07-27 src:macro.c,tests/test_how_to_examples.py conf:high]
  =MONAD_MACRO_TRACE=1= emits one JSON object per expansion with the expansion
  phase, macro name, input AST, and output AST. Tracing is opt-in and normal
  compiler output remains quiet.

[FIX id:fix.macro.quasiquote-depth-2026-07-27 src:macro.c,tests/test_how_to_examples.py conf:high]
  Compile-time quasiquote constructs syntax and evaluates unquote holes at
  depth one. Nested quasiquotes increment depth and preserve inner unquotes
  until their matching quotation level.

[FIX id:fix.macro.user-source-diagnostic-2026-07-27 src:macro.c,tests/test_how_to_examples.py conf:high]
  =syntax-source-*= exposes copied source coordinates, and =syntax-error= lets a
  transformer attach a custom diagnostic to the argument syntax that caused
  it. The diagnostic therefore points to the DSL use site rather than the
  transformer's implementation body.

[FIX id:fix.macro.quasiquote-splicing-2026-07-27 src:macro.c,tests/test_how_to_examples.py conf:high]
  =unquote-splicing= evaluates its expression at quotation depth one, requires
  list Syntax, and inserts cloned elements into the surrounding immutable list.
  Use outside a quasiquoted list and non-list results are source-located errors.

[FIX id:fix.macro.explicit-hygiene-api-2026-07-27 src:macro.c,tests/test_how_to_examples.py conf:high]
  =syntax-gensym= and =syntax-introduce= create globally fresh compiler-safe
  identifiers. =syntax-capture= is the explicit escape hatch that constructs
  an unscoped identifier for intentional use-site capture. Fresh-name tests
  prove distinct introductions cannot collide.

[OBS id:obs.macro.syntax-kind-match-2026-07-27 src:macro.c,tests/test_how_to_examples.py conf:high]
  =syntax-kind= returns a compile-time String describing the immutable node.
  Ordinary Monad =match= lowers to lexical lambdas and conditionals already
  understood by the evaluator, providing structural pattern dispatch without
  a second compiler-only pattern language.

[FIX id:fix.macro.lexical-context-metadata-2026-07-27 src:reader.h,reader.c,macro.c,tests/test_how_to_examples.py conf:high]
  Syntax nodes own optional immutable lexical-context metadata. AST cloning,
  destruction, and JSON tracing preserve it. =syntax-fresh-context= creates a
  fresh context, =syntax-add-context= materializes a compiler-distinct
  identifier while retaining its source spelling, =syntax-context= inspects
  the context, and =syntax-remove-context= is the explicit de-scoping operation.

[FIX id:fix.macro.recursive-syntax-containers-2026-07-27 src:macro.c,tests/test_how_to_examples.py conf:high]
  Compile-time helpers may recursively traverse immutable Syntax lists with
  =syntax-list-tail= and construct them with =syntax-list-cons=. Arrays have a
  distinct syntax kind and are constructed and inspected through
  =syntax-array=, =syntax-array?=, =syntax-array-length=, and
  =syntax-array-ref=; list and array access both perform checked indexing.

[FIX id:fix.macro.evaluation-depth-bound-2026-07-27 src:macro.c,tests/test_how_to_examples.py conf:high]
  Syntax evaluation enforces independent deterministic step and nesting
  limits. The nesting guard is checked before entering the recursive evaluator
  and is reset for each top-level transformation, preventing a recursively
  defined transformer from reaching the host C stack limit. Exhaustion exits
  normally with a source-located compiler error rather than a signal crash.

[FIX id:fix.macro.module-owned-transformers-2026-07-27 src:macro.c,macro.h,main.c,tests/test_how_to_examples.py conf:high]
  Every Syntax transformer records the canonical source file of its defining
  module. Recursive compilation maintains nested expansion scopes containing
  the current owner and only its direct imports. A transformer imported by an
  intermediary module therefore does not leak transitively. A module-local
  transformer shadows imported names; otherwise equal names from two active
  imported owners produce a deterministic ambiguity diagnostic naming both
  source files.

[FIX id:fix.macro.transformer-export-and-definition-scope-2026-07-27 src:macro.c,tests/test_how_to_examples.py conf:high]
  Macro registration derives transformer visibility from the owning module's
  explicit export array. Private transformers remain callable within their
  owner but are invisible across an import boundary. Each transformer captures
  its definition-time direct-import set; evaluation temporarily restores that
  lexical phase environment, allowing an exported transformer to call private
  local helpers or its own imported helpers without dynamically inheriting the
  client's unrelated transformer bindings.
