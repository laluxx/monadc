[OBS id:obs.reader.char-escape-tab src:reader.c conf:high]
  =Char= literals with ='\t'= are handled by Wisp expansion. Wisp converts the
  escape to a tab character before the reader sees it, so the reader receives a
  literal tab character inside single quotes.

[OBS id:obs.reader.char-escape-newline-fails src:wisp.c,reader.c conf:high]
  =Char= literals with ='\n'= fail because Wisp expands =\\n= to a real newline,
  splitting the literal across two lines. The paragraph tokenizer then sees an
  orphan closing ='= token on line 2. This is a Wisp limitation: escape sequences
  that produce whitespace or newline characters cannot be used inside char
  literals in standalone expressions.

[OBS id:obs.reader.buffer-wisp-syntax src:wisp.c conf:high]
  Wisp form =define buffer :: [16kb I32]= expands to
  =(define [buffer :: Arr :: 16kb :: I32] [])=. The =::= syntax inside brackets
  creates a typed variable binding where =Arr= is the array type constructor,
  the size suffix (=kb=, =mb=) is a symbol, and the element type follows.

[OBS id:obs.reader.buffer-paren-syntax src:reader.c conf:high]
  Parenthesized form =(define buffer [16kb I32])= creates a define with an array
  literal as the value. The =[16kb I32]= is parsed as an =AST_ARRAY= containing
  =[(* 16 kb) I32]= where =kb= is a symbol and =*= is inferred as multiplication.

[OBS id:obs.reader.buffer-size-limit src:reader.c conf:high]
  Static arrays exceeding 1gb (=[16gb]=, =[16tb]=) are rejected at compile time
  with "Static array is too large to allocate on x86-64". They still parse
  correctly but fail in codegen. Wisp form also fails since =[16gb]= expands to
  a static array exceeding the limit.

[FIX id:fix.reader.initialized-sized-buffer-next-line-2026-08-25 date:2026-08-25 by:codex src:wisp.c,tests/wisp_initialized_buffer.mon,tests/test_wisp_initialized_buffer.py conf:high]
  A Wisp sized-buffer declaration may place its literal initializer on the
  immediately following line: =define words :: [4 U32]= followed by the
  bracketed words.  Wisp keeps the annotation and initializer in one =define=;
  it must not synthesize an empty buffer and discard the following literal as
  a top-level expression.  The explicit element type is required when the
  representation matters; =[N]= retains its documented =U8= default.

[OBS id:obs.reader.sugar.implicit-mul src:reader.c conf:high]
  Implicit multiplication: when a literal (number, hex, binary, octal, float) is
  immediately adjacent to a variable name (e.g. =3x=, =0xFFx=, =-3y=), the reader
  desugars it to =(* 3 x)=. Greek-letter prefix calls are not yet supported.

[OBS id:obs.reader.sugar.percent src:reader.c conf:high]
  Percentage sugar: =N%= desugars to =N/100=. Float percentages (=3.5%=) and negative
  percentages (=-50%=) are supported. High-precision decimal percentages are
  preserved as exact ratios.

[OBS id:obs.reader.sugar.periodic src:reader.c conf:high]
  Periodic decimal sugar: =0.(3)= desugars to =3/9= (the repeating digit as an exact
  ratio). Multi-digit repeating blocks are supported: =0.(12)= → =12/99=.
  Integer parts preserve the whole: =1.(6)= → =1 + 6/9=.

[OBS id:obs.reader.sugar.superscript src:reader.c conf:high]
  Superscript sugar: Unicode superscript digits (=x²=, =y³=, =x²⁰=) desugar to
  =(^ x 2)=, =(^ y 3)=, =(^ x 20)= respectively. Only whole-number exponents are
  supported.

[OBS id:obs.reader.sugar.ptr-type src:reader.c conf:high]
  Pointer type sugar: =*Int= desugars to =(Pointer Int)=, =**Int= desugars to
  =(Pointer (Pointer Int))=, and so on for any number of star prefixes.

[OBS id:obs.reader.sugar.unicode-prefix src:reader.c conf:high]
  Unicode prefix call sugar: Greek letters immediately adjacent to a form
  (=δx=, =Σexpr=) desugar to prefix calls: =(δ x)=, =(Σ expr)=. The recognized
  prefix characters include δ, γ, ω, Σ (sigma), and the standard sqrt/sin symbols.

[OBS id:obs.reader.sugar.postfix-call src:reader.c conf:high]
  Postfix call sugar: =f(x)= desugars to =(f x)=, allowing function-call syntax
  similar to C/Java. Multiple arguments work: =f(x, y)= → =(f x y)=. Index access:
  =arr[i]= → =(index arr i)=. Chained postfix: =obj.method(arg)= → =(method obj arg)=.

[OBS id:obs.reader.sugar.dot-access src:reader.c conf:high]
  Dot field access sugar: =expr.field= desugars to =(. expr field)=. Nested access
  (=obj.field.subfield=) chains: =(. (. obj field) subfield)=. Works on parenthesized
  expressions and function call results.
  
[OBS id:obs.reader.sugar.assign-arrow src:reader.c conf:high]
  Assignment arrow sugar: =x <- expr= desugars to =(set! x expr)=. This supports
  field mutation: =p.x <- 5= → =(set! p.x 5)= and compound assignments:
  =x <- x + 1= → =(set! x (+ x 1))=.

[OBS id:obs.reader.sugar.pipe src:reader.c conf:high]
  Pipe sugar: =x |> f= desugars to =(f x)=. Pipe chains are handled by the wisp
  transformer, not the reader desugarer. The reader preserves =|>= as infix syntax.

[OBS id:obs.reader.sugar.address-of src:reader.c conf:high]
  Address-of sugar: =&x= desugars to =(address-of x)=. Supports field addressing:
  =&p.x= → =(address-of (. p x))=.

[OBS id:obs.reader.sugar.quasiquote-corner src:reader.c conf:high]
  Quasiquote corner syntax: Unicode corner brackets =⌜expr⌟= desugar to
  =(quasiquote expr)=, and =⌞expr⌟= desugars to =(unquote expr)=. Supports
  quasiquote/unquote splicing for template-based code generation.
  
[OBS id:obs.reader.sugar.cond-to-if src:reader.c conf:high]
  Cond desugaring: =(cond [test1 body1] [test2 body2] [else body3])= desugars to
  nested if expressions: =(if test1 body1 (if test2 body2 body3))=. The =[else
  body]= clause becomes the final branch with no test.

[OBS id:obs.reader.sugar.let-desugar src:reader.c conf:high]
  Let desugaring: =(let [x val] body)= desugars to =((lambda (x) body) val)=.
  Multiple bindings =[x1 v1 x2 v2]= produce nested applications.
  =let*= and =letrec= are desugared into sequences of =let= and =Y= combinator

[THINK id:think.reader.sugar-vs-parser-boundary conf:high]
  The reader's sugar-application design (reader_sugars_apply transforms
  the AST after parsing, before macro expansion) is an unusual choice.
  Most Lisp-family compilers apply syntactic sugar during reading (in
  the reader macro) or after macro expansion. Applying it between parse
  and macro-expand means sugar transforms see the parsed AST structure
  but before any user-defined macros fire. This is both a strength and
  a weakness: sugar can rely on the AST being well-formed (no unexpanded
  macros), but sugar cannot interact with user-defined syntax. The
  consequence is that user-defined macros cannot extend the sugar system
  — if a user wants =(pair 1 2)→(cons 1 (cons 2 nil))=-style sugar,
  they must write a macro, not a sugar rule. This is a deliberate
  limitation that keeps the sugar system small and predictable but
  limits extensibility.

[THINK id:think.reader.error-recovery-strategy conf:medium]
  The current reader uses fail-fast error handling: first parse error
  terminates compilation. This is standard for compilers but frustrating
  for an interactive language that also has a REPL. The parser recovers
  from tokenizer errors (returns error token and continues) but not from
  structural errors (unmatched parens, invalid syntax). Adding error
  recovery to the parser — skipping to the next top-level form on
  syntax error — would make the REPL and batch compilation much more
  forgiving. This is particularly important for a language with macros
  and wisp, where syntax errors can be hard to spot at the s-expression
  level.

[THINK id:think.reader.source-location-cost conf:high]
  Every AST node carries source location info (file:line:col) stored as
  a SourceLoc struct. This is essential for error messages and source
  maps, but it adds ~16 bytes per node (two 32-bit ints plus file index).
  For a 100K-node compilation (not unrealistic for a medium-sized
  program), that's 1.6 MB of source location metadata that is only
  needed for errors. An alternative: store source locations only for
  top-level forms and compute child locations by offset, or use a
  compression scheme (relative positions, delta encoding). The current
  approach is simple and correct — the memory cost is acceptable for
  a compiler running on modern hardware with a 4 MiB arena block size.

[THINK id:think.reader.lexer-peek-ahead conf:high]
  The lexer's extensive use of peek-ahead (peek_char, skip_whitespace,
  peek for keyword detection) makes the tokenizer stateful and somewhat
  fragile. Multi-character operators like -> and :: require the lexer
  to read one char, check if the next char matches, and potentially
  backtrack. This is inherent to tokenizing a language with compound
  operators, but it means the lexer cannot be a simple state machine.
  The current approach is pragmatic: a single linear pass with bounded
  peek (1-2 chars) that never backtracks more than one token. This is
  the right tradeoff for a compiler lexer (throughput matters more than
  elegance) but makes the lexer code harder to reason about.

[THINK id:think.reader.wisp-shared-ast conf:high]
  The shared AST between wisp and s-expression parsing is one of the
  best design decisions in the compiler. Wisp expands to the exact same
  AST nodes as s-expression parsing, which means the entire downstream
  pipeline (macro expand, infer, dep check, codegen) is completely
  agnostic to the source syntax. This is what makes "mixed-mode files"
  possible — a file can start in wisp and switch to s-expr for macro
  definitions without any pipeline changes. The cost is that any AST
  change must be validated against both parser paths, effectively
  doubling the parser test surface.

[DEC id:dec.reader.expected-type-scope date:2026-07-26 by:human]
  A module may declare a grammar with =reader-syntax Type=.  The grammar is
  selected only for an indented expression whose enclosing typed value binding
  explicitly expects =Type=.  Selection by expected type prevents imported DSL
  punctuation from globally capturing arrows used by types, clauses, patterns,
  or iteration.

[OBS id:obs.reader.syntax-declarations src:reader_syntax.c conf:high]
  The initial public declaration vocabulary is =binder=, =prefix=, and =infix=.
  Rules name both their surface token and ordinary target function.  Infix and
  binder rules carry binding power; infix rules additionally declare left or
  right associativity.  The compiler kernel contains no knowledge of logic
  tokens or constructors.

[OBS id:obs.reader.syntax-phase src:wisp.c conf:high]
  Reader-syntax expansion precedes commentary stripping, Wisp tokenization,
  ordinary parsing, and hygienic macro expansion.  It emits canonical source
  forms consumed by the existing shared AST pipeline while retaining original
  line count for diagnostics.

[OBS id:obs.reader.syntax-scope-regression src:tests/reader_syntax_scope.mon conf:high]

[DEC id:dec.reader.bicameral-pipeline-2026-07-29 src:context/reader.org conf:high]
  Monad's programmable syntax follows a bicameral pipeline: reading produces
  source-located groups, delimiters, blocks, atoms, and trivia; scoped
  expansion assigns language meaning; typed core lowering happens only after
  expansion. Reader extensions must not depend on runtime function arity to
  recover grouping that the structural phase discarded.

[DEC id:dec.reader.syntax-provenance-2026-07-29 src:reader_syntax.c conf:high]
  Every introduced syntax node needs an origin class (source, introduced, or
  relocated), an owning reader binding, a phase, and a complete source span.
  Extension lookup is lexical and phase-specific. Two active owners for the
  same trigger are an error rather than an order-dependent choice.

[DEC id:dec.reader.quote-barrier-2026-07-29 src:wisp.c,reader.c conf:high]
  Quote is a structural barrier. Wisp grouping and infix rewriting preserve
  quote-prefixed atoms and delimited data byte-for-byte until the ordinary
  reader constructs the quote AST. Character literals remain distinct because
  they have a closing apostrophe.

[FIX id:fix.wisp-quoted-atom-loss-2026-07-29 src:wisp.c,tests/codegen/branches/wisp-codegen/collections-quote-path/atom.codegen.80.wisp.codegen.collections.quote.path.rt.wisp.quote conf:high]
  Grouped-infix rewriting previously erased a quoted atom in
  =define sym 'hello=. Quote detection now distinguishes quote-prefixed atoms
  from closed character literals before rewriting. The Wisp quote regression
  compiles and its emitted AST retains both symbol and list quotations.

[FIX id:fix.reader.effect-qualification-context-2026-08-03 date:2026-08-03 by:codex src:reader.h,reader.c,tests/test_effect_arrow_syntax.py conf:high]
  Function signatures parse =where row has trait= after the return type.
  Comma and =and= separators are accepted. Lambda ASTs own parallel row/trait
  vectors and preserve them through cloning, printing, and destruction. The
  return-type parser stops before =where=, preventing qualification text from
