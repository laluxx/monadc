[DEC id:dec.type-theory.declarative-judgment-2026-07-30 src:user-request,context/type-theory.org conf:high]
  Use the declarative judgment:

  =Σ ; Ψ | Γ ⊢ℓ e : A ! ε ▷ Δ=

  =Σ= is the global signature, =Ψ= the layered meta-context, =Γ= the graded
  object context, =ℓ= the current layer, =A= the type, =ε= the produced effect
  row, and =Δ= the quantitative usage/coeffect output.

[DEC id:dec.type-theory.algorithmic-judgment-2026-07-30 src:context/type-theory.org conf:high]
  Keep inference constraints on the output side:

  =Σ ; Ψ ; Ξ | Γ ⊢ℓ e ⇑ A ! ε ▷ Δ ⊣ C=

  =Ξ= declares type, grade, effect, region, and layer metavariables. =C=
  contains generated equations and inequalities. The declarative calculus must
  not depend on solver implementation details. Algorithmic soundness must show
  that every solved inference derivation elaborates to a declarative one.

#+CAPTION: Judgment components
| Component | Role                                                        | Structural discipline                        |
|-----------+-------------------------------------------------------------+----------------------------------------------|
| =Σ=         | global types, constructors, modules, effects, FFI contracts | persistent signature extension               |
| =Ψ=         | contextual metavariables and code values from outer layers  | modal/contextual substitution                |
| =Ξ=         | inference metavariable declarations and kinds               | solver-scoped, no runtime meaning            |
| =Γ=         | local binders =x :^q A @ ℓ=                                    | graded weakening/subusage                    |
| =ε=         | produced effect row                                         | row extension, unification, handling         |
| =Δ=         | required use of =Γ=                                           | semimodule sequence/addition and branch join |
| =C=         | generated constraints                                       | solved after inference, never a term context |

Effects and coeffects remain separate. Effects describe what a term does to
its environment; quantitative usage describes what it requires from its
environment. They interact through typing rules but are not forced into one
algebra.

[DEC id:dec.type-theory.graded-arrow-2026-07-30 src:qtt/README.org,types.h conf:high]
  The target authoritative function type is:

  =(x :^q A) →{ε} B=

  Quantity =q= belongs to the binder, not nominal =A=. Effect row =ε= belongs
  to function application. Inference may omit both from source syntax, but
  interfaces and diagnostics must be able to print them.

The current =TYPE_ARROW= carries only parameter and result types. The current
QTT scheme carries correlated grades beside it. Migration must preserve HM
  principal inference while making grade/effect compatibility a type-checking
  obligation. Adding fields without changing application checking does not meet
  this milestone.

[DEC id:dec.type-theory.quiet-bracket-effect-arrow-2026-08-03 src:user-request,context/type-theory.org conf:high]
  Ordinary Monad source keeps the value type visually primary and relies on
  inferred effects, so definitions normally remain =read :: () -> String=.
  When an explicit contract or elaborated/tooling view is requested, the
  preferred effect-arrow spelling is =A -[epsilon]-> B=, for example
  =() -[io.read]-> String=. Empty effects remain quiet, and the older
  =A -{epsilon}-> B= presentation is not the chosen surface syntax. Dense
  higher-order effect variables belong primarily in interfaces and inspection
  tooling; source annotations are optional checking assertions at abstraction
  boundaries rather than mandatory decoration.

[DEC id:dec.type-theory.compact-unbracketed-effect-arrow-2026-08-03 src:user-request,context/type-theory.org conf:high]
  This decision supersedes the bracket spelling in
  =dec.type-theory.quiet-bracket-effect-arrow-2026-08-03=. An explicit or
  elaborated effectful arrow uses the compact form =A -epsilon-> B=, for
  example =a -io.read-> b=. Ordinary inferred source remains =A -> B=; the
  effect spelling is shown only for intentional contracts or inspection.

[DEC id:dec.type-theory.core-owned-effect-vocabulary-2026-08-03 src:user-request,effects/README.org conf:high]
  Core owns the declarative effect vocabulary, operation signatures, handler
  APIs, and trusted primitive contracts as far as bootstrapping permits. The
  compiler owns a generic row/effect-expression calculus, elaboration,
  constraint solving, evidence verification, and lowering; it must not encode
  an indefinitely growing closed list of language effects or recognize
  ordinary core function names to assign semantics. Irreducible runtime/ABI
  primitives expose typed declarations that core wraps. Core compilation is
  the proof-of-existence test that the public effect model is expressible in
  Monad itself.

[DEC id:dec.type-theory.contextual-code-2026-07-30 src:context/type-theory.org conf:high]
  Do not admit unrestricted =box= introduction from an arbitrary object
  context. Closed code requires an empty object context:

  =Σ ; Ψ | · ⊢ℓ+1 M : A ! ∅ ▷ ·=
  =────────────────────────────=
  =Σ ; Ψ | Γ ⊢ℓ box M : □A ! ∅ ▷ ·=

  Open code uses a contextual type =[Γc]A= and explicit substitution. Captured
  resources, effects, and layers must remain visible in the contextual
  environment.

Quotation and splicing receive explicit adjacent-layer rules before arbitrary
natural-number layer polymorphism. =◇A= is reserved until its logic is fixed;
effectful suspension should initially be represented as a computation/thunk
carrying =ε= rather than conflated with modal possibility or unrestricted
=eval=.

  https://www.cs.cmu.edu/~fp/papers/cmtt05.pdf

  https://arxiv.org/abs/2010.13163

[DEC id:dec.type-theory.inferred-effects-2026-07-30 src:user-request,context/memory.org conf:high]
  Effects are inferred by default and quiet when empty. Source annotations are
  optional documentation or checking contracts, not mandatory monadic syntax.
  Begin with extensible rows over =state h=, =exn E=, =io=, =alloc r=, =ffi f=,
  =div=, and =async=. Effect handlers or scoped elimination may remove labels
  only under checked rules.

Effect evidence is required for reclamation: erasure requires an empty
observable effect; exceptions require cleanup edges; state and FFI affect
alias/escape reasoning; async and control effects affect lifetimes.

   fresh instantiation.
2. [X] Establish an executable coherence boundary between typed-Core

   differentially checked; =let=, closure, and application remain named

3. [X] Unify =let= by choosing and documenting one operational semantics,
   proving its quantitative rule, and making both evaluators agree.
4. [ ] Extend authoritative HM arrows to correlated binder-grade and effect
   contracts; application checking consumes both.
5. [ ] Move the current QTT source scheme from shadow verification into that

6. [ ] Complete higher-order unification. Closure construction and fully

   capture/latent/domain premises. Extend the same evidence to indirect,
   imported, returned-closure, and data-stored calls.

   and erasure gates.
8. [ ] Define a two-layer closed quotation/splicing kernel and prove stage
   preservation.
9. [ ] Generalize closed =□A= to contextual code =[Γ]A= with typed explicit

10. [ ] Add effectful suspension only after its distinction from code and modal
   possibility is formal.
11. [ ] Mechanize preservation, grade soundness, effect soundness, stage safety,
   erasure, and Resource-IR lowering simulation for the accepted core.

Exit criteria are executable laws plus compiler integration. Syntax, metadata
fields, and maturity prose alone do not complete a roadmap item.

[DEC id:dec.type-theory.qtt-graded-resumptions-2026-08-01 src:user-request,context/type-theory.org conf:high]
  Every effect operation carries an exact =N union {omega}= resumption grade:
  zero is abortive, one is linear, finite =n= is finitely multi-shot, and
  =omega= is unrestricted. This is the bridge between handler control flow and
  ownership: captured unique resources may move through linear resumptions,
  abort paths require cleanup, and multi-shot capture requires share/copy
  evidence or rejection.

[DEC id:dec.type-theory.closed-effect-join-2026-08-01 src:context/type-theory.org conf:high]
  Closed inferred effect rows form a join-semilattice. Their least upper bound
  is multiset maximum, not concatenation: sequencing the same capability twice
  does not claim two handler instances, while genuinely duplicated scoped
  instances remain distinct. Thus =epsilon join epsilon = epsilon=, join is
  commutative and associative, and branch/sequence composition has a canonical
  order-independent summary. Open-row combination remains constraint solving,
  not this closed operation.

* fix.type-theory.first-production-core-io-boundary-2026-08-04
:PROPERTIES:
:ID: fix.type-theory.first-production-core-io-boundary-2026-08-04
:END:

The first production Core IO boundary distinguishes exact implementation
effects from portable API constraints. =System.Posix.Term.sys-read= and
=sys-write= explicitly quantify a row satisfying =foreign= because their
bodies execute inline assembly. Since Core declares =foreign => io=, the
portable =IO= façade exposes rows satisfying =io= without falsely asserting
that today's syscall body is the nominal =Core.IO.read= operation.

Thus the abstraction relation is

  HasTrait(epsilon, foreign)  foreign <= io
  -------------------------------------------
              HasTrait(epsilon, io).

=IO.read-byte=, =write-byte=, and =write-text= retain explicit descriptors and
return operating-system byte counts/status values. They do not wrap ordinary
values in an IO container and do not allocate a reified instruction list.
Their v12 interfaces transport the staged =io= predicate.

Terminal line editing is factored as =Text.LineEditor=, a pure deterministic
state transition module, and =IO.Readline=, which owns byte acquisition and
terminal-mode lifecycle. The broken historical one-byte String constructor was
not migrated: byte-to-Unicode decoding must become a separately validated IO
layer. The recursive Readline kernel now carries the explicit contract

  Int -> Int -> [Int] -io-> [Int].

The apparent collection/effect-arrow failure was a partial-application parse:
a line break ended the recursive call after its descriptor, giving the branch
the residual type =Int -> ([Int] -e-> [Int])=. Collection indexing coercion is
now restricted to a single pure arrow, so residual or effectful callables retain
the direct collection-versus-function diagnostic instead of being rewritten
into a misleading element-type error. This preserves the separation

  erase(A -epsilon-> B) = A -> B

while keeping effect evidence attached to the corresponding arrow stage.

Above the raw integer-status primitives, =IOError= and the
=read-byte-result=, =write-byte-result=, and =write-text-result= operations
provide typed =Either IOError a= outcomes. Structured reads now consult
=read-buf= directly: zero becomes =IOEndOfInput=, a negative result becomes
=IOStatus n=, and one returns the byte. This avoids the older =read-char=
boundary that collapses EOF and failure.

Regression contract: =tests.test_core_io_effects= executes real read, byte
write, text write, structured byte/EOF results, and Readline key acquisition
through pipes; inspects v12 IO predicate artifacts; and enforces the
pure/effectful module split.
