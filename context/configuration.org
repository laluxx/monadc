[DEC id:dec.configuration.typed-language-owned-2026-07-28 date:2026-07-28 by:human src:user-request conf:high]
  Reusable project configuration is expressed inside Monad itself. A tool
  defines its schema with layouts and algebraic data, and a project provides an
  ordinary typed module value. Configuration may therefore use pure Monad
  functions without introducing YAML, an untyped universal value tree, a
  second parser, or a second evaluator.

[DEC id:dec.configuration.core-protocol-2026-07-28 date:2026-07-28 by:codex src:core/Configuration.mon conf:high]
  =core/Configuration.mon= owns reusable paths, severities, structured
  diagnostics, validation results, requirements, and provenance. Tool-specific
  schemas and precedence rules remain with their tools. Loading a configuration
  module must use ordinary compiler module resolution and static typing.

[OBS id:obs.configuration.literal-reader-2026-07-28 src:core/Configuration.mon,tests/configuration_literal_reader.mon conf:high]
  Importing =Configuration= activates a scoped =configuration_= block reader.
  Its exported Monad Syntax transformer lowers literal =name = expression=
  entries to a typed keyword-constructor definition. Blank lines, comments,
  and indentation arrive through the general reader-block protocol; no
  configuration field name is present in compiler C code.

[OBS id:obs.configuration.reader-generalization-regression-2026-07-28 src:tests/configuration_literal_reader.mon,tests/test_reader_blocks.py conf:high]

  checks run against the same generalized registry and grouping pass used by
  =Web.HTML=.

* Formatter and lint policy
:PROPERTIES:
:ID: monadc.context.configuration.format-policy
:CONTEXT_KIND: architecture
:CONTEXT_STATUS: active
:END:

Formatter policy is typed tool configuration, not scattered command-line
conditionals. Its schema includes map brace placement (=compact=, =hanging=,
or =expanded=), indentation width, maximum docstring summary width, and blank
line counts between top-level declarations, sections, and related definitions.
Lint policy maps stable rule IDs to severities and may require documentation for
selected visibility classes.

The C implementation supplies deterministic defaults and consumes the evaluated
configuration through the ordinary compiler configuration boundary. The LSP,
=monad lint=, and the formatter share the resolved policy object for a workspace.
