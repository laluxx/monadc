* Purpose and claim boundary

This directory is the executable research core for Monad's quantitative type
and resource system. It has two related, deliberately separate goals:

1. a genuine graded typing discipline in which usage participates in whether a
   typed term is valid; and
2. deterministic automatic resource management elaborated into checked
   ownership IR.

The implementation is not yet a complete Atkey/Idris 2-style QTT. In
particular, Monad's authoritative HM/dependent elaborator does not yet construct
graded Π types, and surface programs cannot yet declare multiplicities. The
current graded checker consumes typed Core, checks canonical result types and
subusage constraints, and attaches independently checkable evidence to
signatures. Calling the entire language “state-of-the-art QTT” would therefore
be premature.

* Cycle 100 milestone: from research paths to compiler judgments

Cycle 100 is worth marking. Over the preceding cycles the project moved from
several serious but overlapping quantitative analyses to compiler-owned
judgments, canonical identities, checked ownership transitions, automatic
destruction plans, effect rows, constraint certificates, and evidence that
survives generalization and module boundaries.

The celebration is technical: Cycle 100 fuses direct application and a useful
lambda fragment into the same recursive type/effect derivation introduced for
atoms and containers. Simple ordinary function definitions can therefore be
checked through rules that construct their HM type, latent effect row,
application constraints, staged callee effects, coverage reasons, and
certificate obligations together.

That is impressive progress, earned by repeatedly replacing broad claims with
executable boundaries and regression tests. It remains a research compiler:
higher-order calls, general annotated lambdas, control flow, lexical binding,
effect handlers, dependent QTT, and mechanized preservation remain. Cycle 100
celebrates becoming more real, not pretending to be done.

* Roadmap to literature-grade QTT and automatic reclamation

The combined judgment, inferred-effect plan, and layered/contextual modal
roadmap are specified in
[[file:../context/type-theory.org][context/type-theory.org]]. This document
remains the implementation contract for the quantitative/resource subsystem;
the cross-system context document owns notation shared with effects and
staging.

The effect-row algebra is implemented in =effects/effect.[ch]=. It supports
normalized duplicate-label rows, open tail variables, unification, handling,
generalization, fresh instantiation, constraint solving, and scheme-owned
evidence. It participates in authoritative HM definition inference through
the combined expression judgment; unsupported syntax continues through a
certified conservative fallback.

** Design invariants

- Quantities form a semiring with a compatible subusage preorder. Monad uses
  =ℕ ∪ {ω}= and must not collapse useful exact finite grades to ={0,1,ω}=.
- Quantities belong to binders and function domains, not nominal value types.
- Type usage and runtime usage are distinct. A zero-grade index may construct
  a type but must not survive into runtime Core.
- Quantitative validity and storage ownership are separate judgments. Usage
  evidence alone does not prove alias, lifetime, effect, or destructor safety.
- Surface syntax should normally infer grades. Annotations are optional
  contracts and optimization controls, not mandatory ownership noise.
- Every claimed fragment has an independent executable checker. Unsupported
  constructs remain explicit.

** Semantic generations and authority

There are currently two generations of quantitative semantics.  They are not
synonyms and documentation must not silently transfer a claim from one column
to the other.

| Generation               | Entry point                                           | Meaning                                                                                                                 | Present authority                                                       |
|--------------------------+-------------------------------------------------------+-------------------------------------------------------------------------------------------------------------------------+-------------------------------------------------------------------------|
| typed-Core certificate   | =core/demand/graded/signature/anf=                      | compact structural, path-sensitive demand over already typed Core                                                       | ownership-lowering evidence for its documented fragment                 |
| symbolic source judgment | =bindings/pipeline/elaboration/constraints/environment= | graded substitution, closure construction versus latent demand, correlated polymorphic grades, instance-qualified calls | candidate typing semantics; authoritative only where integrated with HM |

The typed-Core checker is intentionally small and auditable.  Closure
construction and fully applied syntactic lambdas now carry quantitative
evidence, but calls through variables, imported functions, returned closures,
and arbitrary data remain outside this checker's higher-order fragment.  A
valid certificate for an unsupported call shape therefore does *not*
establish the newer source judgment.  Conversely, the source system is not
authoritative merely because it models more cases: it must survive HM
integration, serialization, and independent checking.

The executable boundary is =qtt/coherence.[ch]=.  It independently evaluates
both generations on their proven common fragment: variables, constants,
sequences, path-sensitive conditionals, graded =let= aliases, closure
construction, and fully applied syntactic lambdas.  It reports unknown and
indirect application as an explicit boundary instead of manufacturing
agreement.
=tests/test_qtt_coherence.py= is the regression contract.

[DEC id:dec.qtt.let-resource-demand-2026-07-30 src:qtt/eval.c,qtt/elaboration.c conf:high]
  Monad Core is strict call-by-value: =let x = v in b= evaluates =v= exactly
  once.  Resource demand is a distinct coeffect and follows graded alias
  substitution:

  =U(let x = v in b) = (U(b) ∖ x) + U(b)(x) · U(v)=

  The multiplier counts demand transferred through the value bound to =x=; it
  does not replay effects or computation in =v=.  Erasing an unused initializer
  therefore additionally requires purity and totality evidence.

[DEC id:dec.qtt.closure-construction-demand-2026-07-30 src:qtt/demand.c,qtt/elaboration.c conf:high]

  environment has construction demand one, independently of its latent body
  grade.  Parameters have construction demand zero.  Invocation demand remains
  separate and is multiplied by the call grade.

** Phase A: graded typing kernel

Status: in progress.

Implement =Γ ⊢ e : A ▷ Δ= with canonical TypeIds, subusage =Δ ≤ Γ=, and proof
objects binding source, result type, context, and demand derivations. Exit when
mutating a grade, type, BinderId, source, proof rule, premise, or observed
demand makes checking fail, and uncertified source signatures cannot enter a
module environment.

The first kernel now exists in =qtt/graded.[ch]=. It is upstream of ownership
ANF, but still downstream of the existing type inferencer.

** Phase B: quantities in elaboration and function types

Status: symbolic usage kernel and restricted HM call-site integration in
progress; authoritative lambda checking is not complete.

- Extend elaborated arrow/Π domains with quantity expressions.
- Infer grade variables and constraints for omitted annotations.
- Check annotations during lambda/application elaboration.
- Preserve grades through substitution, unification, zonking, generalization,
  instantiation, cloning, imports, and serialization.
- Specify higher-order domain variance and subusage.

Exit criterion: a source function with allowance one is rejected during typing
when its parameter is consumed twice, before ownership lowering. Polymorphic
instantiations receive independent grade variables where required.

Adding an isolated field to =Type= or =ASTParam= is not sufficient: losing the
field during substitution or polymorphic instantiation would be unsound.

The first substrate is =qtt/constraints.[ch]=:

- immutable constant, variable, addition, and multiplication expressions;
- subusage and equality constraints;
- minimal lower-bound solutions for the currently supported constraint shape;
- inconsistent-bound and direct occurs-cycle rejection;
- generalization relative to a set of rigid environment variables; and
- fresh, independent instantiation of quantified grade variables.

Grade arenas and schemes are immutable and reference counted. A generalized
scheme retains the arena containing its templates, and schemes themselves can
be shared by compiler environments. This permits a scheme to outlive the
inference scope that created it without dangling grade expressions—the
lifetime prerequisite for adding it to HM =TypeScheme=.

Quantitative schemes now have one jointly generalized signature containing
three explicit partitions: outer arrow-domain grades, latent capture-slot
grades, and nested-closure arrow-domain grades. Closure evidence is qualified
by module and stable closure identity; captures additionally use environment
slots while BinderIds remain provenance. Generalizing all partitions together
is essential.
For example, domain =α= and latent demand =α+1= must instantiate with the same
fresh =α=; independently freshening two schemes would destroy that equation.
Cloning a =TypeScheme= retains the complete signature, and quantitative
instantiation returns both partitions while arrow-arity validation considers
only the domain partition.

HM application inference now creates a *paired quantitative instance* rather
than independently freshening a type and an unrelated grade vector.  For an
instantiated arrow

  =(x₁ : A₁) → ... → (xₙ : Aₙ) → B=

the scheme must instantiate exactly =n= domain grades
=ρ₁ ... ρₙ=.  A malformed scheme is rejected during inference.  Partial and
full direct applications advance the arrow and grade prefixes together, and
the =InferCtx= retains an application record binding the source AST identity to
the applied grade prefix.  This record is the handoff point for future
call-site grade constraints and ownership lowering; it is not yet a proof that
an argument expression satisfies the corresponding grade.

The symbolic elaboration kernel in =qtt/elaboration.[ch]= supplies the
semimodule action needed to turn those domain grades into caller demand.  If
=U(e)= maps free BinderIds to symbolic grades, its executable rules are:

  =U(x) = [x ↦ 1]=

  =U(e₁ ; e₂) = U(e₁) + U(e₂)=

  =U(if c then t else f) = U(c) + (U(t) ⊔ U(f))=

  =U(f a₁ ... aₙ) = U(f) + Σᵢ ρᵢ · U(aᵢ)=

  =U(let x = v in b) = (U(b) ∖ x) + U(b)(x) · U(v)=

  =C(λx.e) = support(U(e) ∖ x)=

  =L(λx.e) = U(e) ∖ x=

  =U(invoke_k closure) = k · L(closure)=

For a closure value returned by a known producer =f ā=, its environment is a
slot substitution =σ= from each captured slot to the producer argument that
supplied it. If =D_c= is closure =c='s own graded domain vector, the implemented
single-invocation rule is:

  =U((f ā) b̄) = U(f ā) + ⨆_{c ∈ results(f)}
                    (Σᵢ D_c(i) · U(bᵢ) + Σ_s L_c(s) · U(σ_c(s)))=

The join is pointwise maximum because one result alternative is selected.
This distinction matters: summing alternatives would overstate exclusive
branches, while selecting one arbitrarily could undercount and free early.

Here =+= is pointwise grade addition, =⊔= is pointwise maximum for one
exclusive execution path, and scalar multiplication is the action of a
function-domain grade on an argument's free-variable demand. Missing binders
denote zero. BinderIds, rather than source names, prevent shadowing from
conflating contexts. =C= is closure-construction demand: every stored free
variable is captured once regardless of its number of latent uses. =L= is the
body demand incurred per invocation. Conflating those two contexts would
either over-count closure creation or under-count repeated calls.

Observed binder demand =δ= is checked against an allowance =ρ= by emitting the
subusage constraint =δ ≤ ρ=. The same symbolic expressions—including
exclusive-choice maxima—survive grade generalization and receive fresh
variables at instantiation. This is the mathematical rule required to connect
Cycle 26 call-site evidence to lambda contracts.

The authoritative source traversal now runs during ordinary HM definition
inference by default. It uses deterministic lexical BinderIds, derives exact
sequence and branch demand, consumes instantiated direct-call grades, and
generalizes the resulting symbolic parameter vector directly into the real HM
=TypeScheme=. A grade-two callee therefore makes a forwarding caller grade two
even when the caller contains only one textual occurrence of its parameter.
=MONAD_QTT_SHADOW= now enables detailed comparison diagnostics only; it no
longer decides whether grade analysis exists. =MONAD_QTT_ANALYSIS=0= is an
explicit rollout escape hatch that disables both grade attachment and
evidence-backed memory lowering.

After inference and dependent checking, the production compiler now runs a
distinct quantitative-ownership phase over the final top-level source forms,
before LLVM function predeclaration and code generation.  This is not
conditioned on =MONAD_QTT_SHADOW=: diagnostics merely make its stable
=verified/unsupported/internal= summary visible.  Each local lambda definition
is lowered and ordinarily verified, unsupported definitions retain
conservative code generation, and an internal verifier failure is
distinguished from an unsupported language fragment.  The phase receives the
compile unit's stable source identity directly; it must not consult the
parser's mutable current-filename state after imports.

This is the first explicit first-class phase boundary, but not yet the final
architecture.  Its successful ANF programs are currently discarded after
verification, while the narrow String-cleanup backend independently requests
Semantic-IR evidence.  The next integration step is to retain per-definition
Semantic-IR/ANF certificates in the compiler module, make interfaces and
backend ownership decisions query those certificates, and retire the
diagnostic-era =shadow= naming from the verifier API.

The core library is also an empirical integration corpus, but a successful
compile is not itself reclamation evidence.  The release gate must record, per
module, the number of verified, unsupported, and internally failed
definitions; inspect emitted LLVM for certificate-authorized destructor calls;
and execute allocation/free-sensitive programs.  A compile in which QTT falls
back for every definition proves compatibility, not reclamation.

The first measured baseline (2026-07-31) compiled and executed a program
against the complete default core with =--emit-llvm --trace=qtt-all=.  Compilation
and execution succeeded, and the focused production-memory suite passed all
eleven LLVM/runtime tests, but the core audit reported zero verified
definitions, 166 unsupported definitions, and three internal failures (all
three in =Data/Maybe.mon=).  This is intentionally recorded as a failing
coverage baseline, not hidden behind the successful build.  “Core-wide
automatic reclamation works” becomes an honest claim only when internal
failures are zero, supported owned allocations have matching certified
destruction in LLVM, runtime accounting balances, and the unsupported count is
reduced to an explicitly reviewed boundary.

Unknown calls never silently default to grade one. A small explicit set of
strict linear primitives uses one; calls carrying quantitative HM evidence use
that evidence; every other call makes this source fragment unsupported and
leaves the HM scheme without quantitative evidence.  The older shadow
derivation remains available for comparison diagnostics but is never installed
as an authoritative fallback.  Assuming linearity for an unclassified foreign
or higher-order callee could undercount usage and eventually cause premature
reclamation.

The traversal currently supports literals, variables, multi-expression lambda
bodies, arrays, sets, =begin=, =if=, sequential =with=/=let= bindings,
classified strict primitives, nested closure construction, and direct calls
with retained quantitative instances. Local bindings are eliminated from last
to first, so a later initializer may depend quantitatively on an earlier local
and same-name shadowing remains correct by BinderId.

The zero-use =let= rule is admitted only for a syntactically classified
pure-total initializer. Known observable calls such as =show=, known partial
operations such as division and remainder, and unknown calls make the source
derivation unsupported. This conservative gate prevents an eventual consumer
from interpreting grade zero as permission to erase effects or divergence.
It is not yet a language effect proof: it rejects effectful initializers even
when their local result is used and it cannot infer effects through arbitrary
callees.

Nested lambda construction contributes capture demand once. Each lambda
receives a deterministic preorder =ClosureId= during lexical resolution. The
source traversal records every nonzero latent entry as
=(ModuleId, ClosureId, CaptureSlot, BinderId, ParameterOrigin, grade)= and
jointly generalizes those entries with the outer function's domain grades into
its real =TypeScheme=. =CaptureSlot= is the operational environment address;
=BinderId= remains lexical provenance and must not be used as a cross-module
substitution key. =ParameterOrigin= is either the outer function parameter
index supplying that slot or =SIZE_MAX= when the captured value is local.
Quantitative instantiation and retained application evidence preserve this
slot map and its correlated grade variables.

Schemes additionally carry a canonical set of qualified closure identities
that may be returned. Direct syntactic lambdas, =begin= tails, =if=
alternatives, and local-body tails contribute result provenance. A full direct
call retains and forwards its callee's result-closure set; a partial call does
not falsely claim the eventual result. This is the first interprocedural
higher-order value-flow evidence.

Known returned closures now have a jointly generalized graded domain vector as
well as their latent capture vector. The source checker substitutes producer
arguments through =ParameterOrigin=, scales actual invocation arguments by the
closure-domain grades, and joins multiple result alternatives by maximum. This
is the first sound higher-order calling rule in the real HM source pipeline.
It is exercised by direct, unused-capture, and conditional two-closure
fixtures.

The rule is intentionally partial. Qualified identities remain in memory but
are not serialized in module interfaces. Function-valued parameters and
closures stored in arbitrary data structures do not yet carry a closure
summary.

Every fully applied factory call now allocates nonzero, overflow-checked
=ClosureInstanceId=s for its returned alternatives. Different application
sites and different alternatives cannot alias even when they share a static
=(ModuleId, ClosureId)=. The source derivation records every instance it
invokes, and repeated factory sites therefore remain separate evidence.
Partial applications do not allocate result instances.

Transitive forwarding now preserves each captured slot's existential origin.
Root parameters remain substitutable, while lexical-local and expression
origins retain their kind and opaque identity through grade generalization and
instantiation. Consequently =((forward x) y)=, complex producer arguments, and
forwarded locals receive quantitative derivations without fabricating a
parameter index or replaying a captured expression. The signature remains
qualified by static closure identity; every concrete factory application then
allocates a fresh instance and substitutes its parameter origins.

This is still expression-level forwarding, not arbitrary closure flow.
General function-valued parameters, data-structure fields, pattern extraction,
unknown calls, and module-interface serialization remain outside the
authoritative source fragment.

Lexical =with=/=let= bindings now carry known closure application evidence in a
BinderId-scoped alias environment. A bound factory result, and a chain of local
aliases to it, therefore retain the original =ClosureInstanceId=, result
alternatives, graded domains, and existential capture environment. Invocation
through the local name uses exactly the same rule as direct invocation.
Bindings leave the alias environment at lexical scope exit, so shadowing
cannot leak evidence between distinct BinderIds.

Only quantitatively known closure-producing applications are admitted as pure
closure initializers by this rule. It does not infer purity for arbitrary
unknown calls. The current quantitative let equation can erase an unused pure
factory. Repeated use still follows the existing substitution/recomputation
semantics; choosing sharing or memoization from inferred usage requires an
explicit evaluation-strategy pass and is not silently assumed here.

The first function-valued parameter contract is also executable. A callable
parameter may be certified with a path-sensitive invocation grade and
principal symbolic argument-domain grades. Its parameter index, invocation
expression, and domain expressions are generalized with the HM grade scheme,
validated, freshly instantiated, and retained on the concrete application record. When
the actual argument is a known closure factory result or lexical closure
alias, the call scales that exact instance-qualified latent environment by the
invocation grade. Construction demand and latent invocation demand remain
separate.

For example, if =apply-constant f = f 1= and =capture x= stores =x= with latent
grade two, then:

  =U(apply-constant (capture x)) = 1 · C(capture x) + 1 · L(capture x) = 3=

Callable parameters now carry an invocation grade rather than a Boolean
“called” marker.  For the checked, non-recursive call-by-value fragment the
elaboration judgment records

  =Γ ⊢ f :^q (A → B)=

where =q ∈ ℕ ∪ {ω}= is the path-sensitive upper bound on forcing =f=.  Passing
a known closure value =v= uses the decomposition

  =Dcall(v, q) = C(v) + q · L(v)=

where =C= is construction demand and =L= is the latent capture demand of one
invocation.  This is deliberately not =q · (C + L)=: Monad evaluates the
closure-producing argument once before the callee can invoke the resulting
value.  Sequential invocation composes grades by semiring addition; exclusive
branches compose them by maximum:

  =q(begin e1 e2) = q(e1) + q(e2)=
  =q(if c e1 e2) = max(q(e1), q(e2))=

The implementation preserves these equations through generalization and fresh
HM instantiation.  The regression witnesses are executable:

- two sequential invocations of a closure with =C(x)=1= and =L(x)=2= derive
  =1 + 2·2 = 5=;
- one invocation in either branch derives =1 + max(1,1)·2 = 3=; and
- missing invocation-grade evidence makes a signature malformed.

For this fragment, the safety argument is structural.  The source usage
derivation supplies =q= using the same sequence and choice rules as binder
demand.  Generalization serializes =q= in the same correlated expression
vector as domain and closure grades.  Instantiation freshens that whole vector
together.  At a known call site, closure construction is charged once and the
instance-qualified latent environment is scaled by the instantiated =q=.
Therefore every dynamic force represented by the derivation is covered by one
copy of =L=, while mutually exclusive forces are not added.

This is an executable proof boundary, not yet a mechanized metatheorem for
Monad.  It assumes a non-recursive statically known callee, a known
closure-producing actual argument with complete domain evidence, ordinary
call-by-value evaluation, and no exception or continuation that duplicates or
re-enters the call. Programs outside that boundary remain unsupported.
Recursive higher-order flow will require a least-fixed-point constraint over
invocation grades; effects and continuations require an effect-indexed
operational semantics before this equation can be promoted to a language-wide
soundness theorem.

Callable argument domains now have principal symbolic grades.  For a function

  =apply : (f : Fn) → (x : A) → B=
  =apply f x = f x=

source elaboration introduces a fresh =β= for the first domain of =f= and
derives =Uapply(x)=β=.  The grade is generalized in the same scheme as
invocation and capture grades.  If a call site passes a known closure whose
first domain grade is =d=, specialization performs the capture-avoiding grade
substitution =[d/β]Uapply=.  Thus passing a closure that consumes its argument
twice derives =[2/β]β=2= instead of rejecting the open argument or guessing
grade one.

For a producer with result alternatives =c₁ … cₙ=, the safe domain
specialization is

  =dᵢ = max(domain(c₁,i), …, domain(cₙ,i))=.

This is the least upper bound in the natural preorder of =ℕ ∪ {ω}= and is
therefore admissible by subusage: whichever closure is returned, its actual
demand is bounded by =dᵢ=.  Separate domain indices retain correlations for
multi-argument functions.  Generalization rejects orphan domain evidence,
duplicate =(callable parameter, domain index)= keys, and missing grade
expressions.  HM instantiation freshens the domain variables with the rest of
the quantitative signature.

The executable witnesses cover:

- =[3/β](β+β)=6= for structural grade substitution;
- an open one-argument application specialized from =β= to =2=;
- a two-argument closure specialized independently to domain grades =1,2=;
  and
- alternative closures joined to their safe maximum domain grade.

This is deliberately narrower than a complete higher-rank graded arrow.
Callable results, escaping callable parameters, partial application of
callable contracts, unknown closure actuals, and recursive or effect-dependent
domain constraints remain unsupported.  In particular, the current =Fn=
surface type does not yet expose =β= as user-written type syntax: the
quantitative scheme carries it alongside the HM type.  Moving it into the
authoritative typing judgment requires a graded arrow constructor and
subsumption rule, not merely more source-demand metadata.

The first explicit environment calculus now lives in
=qtt/environment.[ch]=. A checked closure value separates its static code
identity from its dynamic instance and existential environment:

  =∃ε. Closure(ModuleId, ClosureId, ClosureInstanceId, ε)=

Each dense environment slot has one origin: a function parameter, a lexical
local BinderId, or a compilation-local expression identity. Environment substitution
replaces parameter origins with actual origins while preserving local and
expression provenance. Zero identities, out-of-range parameters, malformed
origins, and unbound substitutions are rejected.

The calculus is now wired into retained HM application evidence. Every fully
applied known factory constructs one environment per result alternative and
substitutes its actual arguments before the application record is published.
Direct higher-order invocation consumes that instance-qualified environment:

- a slot originating at a caller BinderId contributes its latent grade;
- a slot originating at a callee-local BinderId remains valid provenance but
  contributes no demand to the caller's quantitative context; and
- an expression-origin slot denotes the already-evaluated captured result.
  Its expression is charged by the producer's ordinary domain grade at
  construction and is not symbolically replayed at invocation.

This distinction makes direct and transitively forwarded invocation through
local and non-variable captures derivable without fabricating a source
parameter. It is regression tested by =qtt-invoke-local=,
=qtt-invoke-complex-capture=, =qtt-invoke-forward-complex=,
=qtt-invoke-forward-local=, =qtt-invoke-bound=, and
=qtt-invoke-bound-alias= in =tests/test_qtt_pipeline.py=. The environment is
still transient compiler evidence: it is not serialized in HM/module
interfaces, propagated through function parameters or data structures, or
consumed by ownership ANF.

The solver is intentionally not advertised as complete Presburger or semiring
constraint solving. General nonlinear inequalities, variable-to-variable
upper-bound propagation, recursive systems, principal-solution proofs, and
diagnostic constraint paths remain future work. Unsupported shapes must acquire
an explicit result and test before the authoritative type checker depends on
them.

Function parameter contracts now distinguish the *allowance* from the
*observed demand*. This matters even before symbolic schemes reach HM:
allowance =ω= can validate a body observed at one, while allowance zero rejects
it. Ownership classification continues to use observed operational behavior;
the allowance is a typing contract and must not be mistaken for an instruction
to duplicate a value =ω= times.

Status: not started.

- Add graded Π types =(x :ρ A) → B= to the dependent term language.
- Separate type-level and runtime quantitative contexts.
- Permit zero-grade indices in types while rejecting their runtime inspection.
- Erase checked dependent terms into runtime Core with a certificate.

Exit criterion: length/proof-indexed programs erase every zero-grade index, and
an independent checker proves runtime Core neither stores nor observes it.

** Phase D: higher-order and recursive grades

Status: qualified closure summaries, result provenance, existential

- Separate closure capture grades from invocation grades.
- Add graded modalities for zero, one, finite-many, and unbounded invocation.
- Extend the implemented descending must-transfer solution to quantitative

- Require loop resource invariants; widen to =ω= only at explicit boundaries.
- Explain the constraint path responsible for every conservative widening.

** Phase E: loans, effects, sharing, and FFI

Status: executable lexical loan kernel and inferred row-effect algebra;
source mutation, lifetime-polymorphic results, sharing, and FFI remain open.

- Root- and projection-indexed shared/exclusive loans with exact lexical close.
- Conservative overlap checking: a whole root conflicts with every projected
  loan, equal projections conflict, and certified sibling projections are
  disjoint.
- Exact alias authority for writes and whole-owner moves; projected moves
  transform an explicit partial-initialization mask and require exclusive

- Canonical place-qualified read/write labels shared by the Resource IR and

- Verified dup/drop for shared representations.
- Effects for mutation, exceptions, continuation capture, concurrency, and

- C ABI ownership/destructor and callback escape contracts.

** Phase F: verified production reclamation

Status: executable acyclic ANF, Semantic-IR-owned lexical cleanup evidence,
checked closure-field layout contracts, and a default-on authoritative LLVM
cleanup slice supporting multiple dead lexical String bindings and fresh
owned results of canonical same-module and source-compiled imported calls.

- Canonical representation and destructor identities.
- Structural drop plans for layouts, ADTs, arrays, and closures.
- Lower verified call/move/drop/dup/region operations through the production IR
  to LLVM.
- Differentially execute Core, ownership ANF, and generated programs.

Exit criterion: production codegen consumes verified ownership programs for the
supported fragment, and instrumented executions agree on allocations, moves,
drops, and escapes.

The first production slice is intentionally narrow and evidence-gated.
By default, a lexical =with= containing one or more dead String bindings may
lower static literals to owned =strdup= allocations and may transfer a fresh
owned result from a canonical same-module call directly into the local
capability. Imported calls use the same result contract registered under the
consumer-visible qualified or unqualified name. Both forms are followed by
reverse-order =free= operations after
the body.
=qtt/backend.c= accepts the source construct only when independently verified
Semantic IR contains exactly one corresponding =ALLOC(OWNED_HEAP)= and
reverse-scope =DROP= for each fresh owned direct binder, every resolved source
=BinderId= agrees with that plan, and every structural String destructor
descriptor verifies. Heap-shaped alias bindings may occur between those
operations, but do not introduce a second capability: their uses retain the
original allocation identity, and an escaping alias moves that identity.
Call-backed initializers additionally require a canonical signature whose
result contract is =OWNED_HEAP=, =OWNED=, and =FRESH=; the call-aware resource
judgment checks parameter borrow/move modes and Semantic IR reconstructs the
same evidence. Code generation additionally requires each qualified resource
identity, owned representation, source binding index, materialization mode,
and both destructor fingerprints before emitting cleanup. An escaping
binding—including a fresh result moved to the caller or a partially escaping
multi-binding scope—an explicit =MONAD_QTT_MEMORY=0= override, or any
unsupported source shape
continues through unchanged legacy code generation.  This is real production
LLVM consumption for one fragment; it is not yet general lexical ownership,
structural destruction, or a default language memory model.

Nested lexical scopes are supported. A scope's direct owned binders must have
matching allocations in its verified resource plan and its drops must be the
exact reverse-order suffix; independently verified alias and nested resource
operations may occur between them. Direct heap-shaped binders without a
materialization contract are rejected if the plan claims they allocate.
This lets inner cleanup execute before outer cleanup without flattening scope
identity or trusting codegen to invent a destruction order.

Source-compiled imports now participate in this judgment through a persistent
interface boundary. The provider emits a versioned =.mqti= sidecar, reloads it,
and consumers register its deserialized ownership signature under each visible
qualified or unqualified name. Interface fingerprints use structural type
fingerprints rather than compilation-local =TypeId= allocation order. Version,
grammar, enum domains, supported type forms, and the complete quantitative
contract digest are checked before evidence enters the consumer environment.
A borrowed/static imported result cannot authorize a local drop. A local
definition transactionally replaces a same-named imported contract, so
ordinary language shadowing cannot leave stale ownership evidence.

Version 1 is intentionally restricted to closed flat ABI types, which covers
the production String reclamation slice. Unsupported composite, polymorphic,
layout, and recursive contracts are omitted rather than approximated. Each
interface records a content fingerprint of the exact emitted object; cached
imports accept quantitative authority only when the current object bytes match
that fingerprint. Missing, malformed, or mismatched sidecars disable QTT
reclamation for that provider while ordinary legacy compilation remains
available. Cached dependencies still rerun source analysis to reconstruct
ordinary export/type metadata, so this is a complete QTT-interface cache
boundary for the supported fragment, not yet complete object-only compilation.

Compiler observability follows the ordinary verbosity convention:

- normal compilation runs supported QTT analysis and memory lowering silently;
- =-v= prints the quantitative-ownership phase and a per-module count of
  registered definitions and canonical contracts;
- =-vv= prints path-sensitive binder grades, canonical result
  mode/origin/representation contracts, contract fingerprints, and each
  certified reclamation consumed by LLVM;
- =--trace=qtt= prints a compact user-module verdict, verified/total coverage,
  conservative fallbacks, and errors. Partial results point directly to the
  proof command, without proof trees or imported-module chatter;
- =--trace=qtt-proof= prints binder grades, contracts, reclamation decisions,
  and the complete evidence tree for the user module only;
- =--trace=qtt-all= additionally exposes imported modules, interface
  contracts, and conservative fallback diagnostics for compiler development.

This progressive-disclosure boundary is intentional. The ordinary question
“did quantitative ownership verify my program?” should fit on a few lines;
proof auditing and dependency debugging are separate questions. =-v= follows
the summary level and =-vv= follows the user-module proof level.

In colored terminals, proof-tree field labels are cyan, successful obligations
and =✓= marks are green, conservative states are yellow, and internal failures
are red. Color distinguishes the name of a semantic field from its value; it
does not color whole subtrees or encode information unavailable in plain text.

These messages describe the production pipeline, not a second diagnostic
analysis. In particular, a line such as
=reclaim text#2 materialization=owned-result destructor=free= is emitted at
the point where codegen consumes a verified cleanup certificate.

The first Semantic-IR bridge now exists for first-order lexical Core. Resource
IR creates capabilities only for =OWNED_HEAP= values. Immediate, inline, and
foreign bindings have no local destruction authority; unknown representation
is rejected rather than guessed. The resource checker separately establishes
linear balance and correspondence to Core, since a balanced =move= cannot be
substituted for a required =drop=. The correspondence checker directly consumes
Core and the submitted plan rather than rerunning the producer. Semantic IR
owns the resulting plan and rechecks it. This does not yet prove loans, sharing, exceptional cleanup,
closure environments, FFI retention, or structural destructor correctness.

The bridge now carries canonical destructor descriptors for owned bindings.
Their identity combines structural type and recursive plan fingerprints;
recursive backreferences use structural distance rather than allocation
addresses. Semantic IR additionally carries explicit per-operation capability
transitions and rejects altered transition or destructor evidence.

Physical closure layout is no longer an untyped list of variables.
=qtt/closure.[ch]= now derives, fingerprints, and independently rechecks each
field's exact Core binder, slot, structural type, representation, transfer
mode, and destructor descriptor. Closure construction retains only
=OWNED_HEAP= captures; immediate, trivial inline, and foreign captures are
copied as values. Destruction releases exactly the retained slots. A layout
contract can be bound to the symbolic existential =QttClosureEnvironment=,
which checks instance/module/closure identity and resolves parameter or local
origins to the exact captured BinderIds. Reordered origins and altered layout
or destructor certificates are rejected.

This unification also exposed and closed a representation/destruction error:
an inline representation does not imply a trivial destructor. Inline layouts
and fixed arrays now receive structural drop plans when their elements require
them. Closure capture of such an aggregate is deliberately rejected until
Resource IR can express projected retains for owned subfields. Expression
origins are likewise rejected by the physical bridge because they do not yet
have a stable Core capability. These are explicit soundness boundaries, not
silent heap-pointer approximations.

Closure construction now has two distinct checked rules. For a uniquely owned
environment,

  =Γ, x : owned ⟶ rehome(x, env[i]) ⟶ Γ, env[i] : owned=

transfers the capability to its qualified field identity without incrementing
a reference count. For a shared/escaping environment,

  =Γ, x : owned ⟶ dup(x, env[i]) ⟶ Γ, x : shared, env[i] : shared=

retains the allocation. The heap evaluator preserves allocation identity across
=rehome= and records no retain/release traffic. Field identity is
=(StorageModule, ClosureId, InstanceId, FieldOrdinal)=; temporary Resource-IR
variables are not treated as globally sufficient location identity.

The first independently checkable closure-policy analysis now selects the
unique rule only for a deliberately small theorem-shaped fragment: the lambda
has exactly one structural Core occurrence and that occurrence is the immediate
callee of exactly one application. Returning, storing, argument-passing,
missing lambdas, and aliased Core DAG occurrences select shared storage. The
evidence records the occurrence count, direct-callee count, and decision
reason; Semantic IR carries it on every lambda and recomputes it during
verification. Physical plan construction can consume this same certificate,
so it cannot independently choose =rehome=. This proves non-escape only for the
single direct-call syntax rule. A small forward may-liveness analysis follows
Core evaluation order through callee-before-arguments, =let=, sequence, and
path-sensitive conditional alternatives. Every captured BinderId must be dead
on all continuations after closure construction. Earlier uses are accepted;
call-argument uses, later sequential uses, reachable post-branch uses, and
captures by a later closure select shared storage. Uses confined to the
opposite branch of the construction are not falsely ordered after it.

The certificate now also classifies each captured field at invocation exit.
Exact tail return through variables, sequence, =let= bodies, and agreeing
conditional arms yields =MOVE_OUT=; a field absent from the result yields
=RELEASE=. Disagreeing conditional arms, capture aliases introduced in =let=
values, and opaque applications or nested closures involving the field are
=UNSUPPORTED= and disable unique storage. The disposition is part of the
physical field fingerprint and verifier. Finalization emits =move env[i]= for
returned fields and =drop env[i]= for released fields, closing the lifecycle
started by =rehome= without double consumption.

Semantic IR now owns one canonical record for every static closure field:
closure node and identity, ordinal, exact source BinderId, canonical =TypeId=,
structural type, representation, storage policy, exit disposition, and
destructor descriptor. Verification independently reconstructs this vector.
The separate =semantic_closure= correspondence judgment accepts a physical
plan only when every structural field agrees with the already-verified
Semantic record. Capture-type lookup is centralized in Typed Core rather than
duplicated between these producers.

Ownership ANF now has an explicit dense environment-slot interface rather than
an untyped hidden-parameter convention. =semantic_anf= materializes each slot
only from verified Semantic-IR field evidence and checks closure identity,
ordinal, source BinderId, canonical =TypeId=, representation, owned/shared
capability, exit disposition, and destructor identity. Unique direct-call
closures therefore enter ANF with owned move-out/release capabilities, while
escaping closures enter with shared release capabilities. Slot forgery and
attempted rematerialization are rejected.

Ownership ANF also has an explicit environment projection instruction. Its
ordinary verifier requires a real certified slot, exact source provenance and
representation, and permits move projection only from an owned slot. The
Semantic correspondence judgment independently checks projection completeness
against Core capture occurrences and requires exactly one final move for a
unique =MOVE_OUT= field. A forged closure identity, ordinal, source, action, or
missing projection is rejected. The standalone evaluator deliberately reports
an unsupported-environment result until it is supplied an actual closure
payload; it never fabricates a projected runtime value.

The automatic producer now lowers captured variables, literals, sequences, and
nested conditionals. It derives each field's remaining demand, emits borrow
projections for non-final uses, emits the certified final move for =MOVE_OUT=,
and emits a projection-qualified release for =RELEASE=. At a conditional it
splits the per-field quantitative state, lowers both arms independently,
requires equal post-arm state, and rejoins through a typed block parameter.
Mixed environments are supported: one field can move out along each result
arm while another stays live through the join and is released afterward.

Projection correspondence independently reconstructs preorder branch
identities and exact then/else control paths from Core. Thus a forged arm path
or branch ordinal is rejected even if aggregate occurrence counts still agree.
The generated program must pass this correspondence check and ordinary ANF
linear-resource verification before it is returned.

Lexical =let= is now accepted for immediate and inline SSA values. Local
BinderIds map to typed ANF values, and their uses become explicit aliases;
branch-local lets compose with path-sensitive capture lowering and typed joins.
Heap-valued lets are deliberately rejected in this fragment. In particular, a
captured owned field cannot be hidden behind an ordinary lexical alias: doing
so would erase the field capability and invalidate the projection proof.

The remaining shadow boundary is broader instruction production: parameters
mixed with captures, nested closures, heap-owning local bindings, indirect
calls, and shared environments are not accepted by this producer yet.
Shared results still require explicit retain/release semantics. Effects,
callbacks, loops, arbitrary value flow, and interprocedural lifetime inference
also remain absent.

Signature-known calls with immediate/inline SSA arguments are now accepted.
The producer resolves the canonical callable contract, validates the call plan,
and emits call evidence with callable identity, contract fingerprint, canonical
argument/result types, transfer modes, call ordinal, and exact branch path.
Both ordinary ANF verification and Semantic call correspondence must accept the
result. Calls may occur inside conditional arms and coexist with branch-local
capture borrows followed by a joined release.

Exact captured variables may now be passed as owned-heap arguments to
signature-known functions. The environment-aware closure-policy judgment
resolves the canonical signature and derives =MOVE_OUT= for a consumed
parameter or =RELEASE= for a borrowed parameter. Semantic IR records and
rechecks that same judgment; closure-body ANF then emits a correspondingly
provenanced =ENV_MOVE=/=CALL_MOVE= or
=ENV_BORROW=/=CALL_BORROW= followed by the field release. Projection
correspondence descends into call arguments and checks the field access
one-to-one.

The conservative boundary remains intentional: only an exact capture variable
is transferable. Opaque callees, stale signature fingerprints, aliases,
multiple occurrences, and nested argument expressions force shared storage
rather than guessing provenance.

Physical closure plans now consume the same signature environment. Inference,
certificate verification, and binding to a concrete closure instance all
derive field exit disposition from the canonical call contract. Semantic
closure correspondence retrieves the environment and module identity already
owned by Semantic IR, avoiding a second caller-supplied authority.

Closure-body lowering now carries a small evaluation-context judgment
=U ∈ {escape, discard}=. Sequence prefixes are checked under =discard=, the
sequence tail inherits its surrounding use, and both conditional arms inherit
the same use. A signature-known owned result under =escape= is moved into the
resulting SSA value; under =discard= it is dropped immediately. This supports
owned results in tail branches as well as automatic reclamation of ignored
straight-line and branch-local results.

Owned result capabilities have a canonical Semantic identity derived from the
qualified pair =(ModuleId, CallOrdinal)= in the compiler-reserved binder
domain. Semantic IR records that exact identity, independently reconstructs it,
and requires Semantic ANF to use the same resource—not merely any nonzero
identifier. Ordinary ANF separately proves unique consumption and an empty live
set at return or branch join.

The first downstream consumer is =qtt/semantic_anf.[ch]=. Its current
single-block and one-conditional fragments require verified Semantic IR and
check that ANF's ownership operations exactly realize the certified
transitions. Conditional edges carry transition slices plus exact qualified
capability-context fingerprints; equal cardinality alone is not accepted as
context equality. Ordinary immediate/inline/foreign bindings remain SSA values
and never enter the capability context. This applies at function and inlined
lambda boundaries as well as lexical =let=: quantitative consumption of an
immediate argument does not manufacture a bind/move/drop obligation. Stable
preorder branch identities now admit nested resource-free conditionals and are
checked for completeness and uniqueness. Ownership instructions now additionally
carry an exact control path—a sequence of branch identity and then/else
choices—and a unique Semantic-IR transition ordinal. This admits nested
ownership-bearing conditionals without scanning ANF storage order. The ordinary
ANF verifier checks operational resource safety; the correspondence verifier
separately checks that these explicit identities realize the certified
Semantic-IR transitions.

** Human-readable evidence trees

Explicit QTT tracing is a semantic observability contract, not an unstructured
debug dump.  With =--trace=qtt-proof= (or the transitional
=MONAD_QTT_SHADOW=1= diagnostic switch), the first-class compiler phase emits
one derivation-shaped evidence tree per direct source lambda:

#+begin_example
[qtt] Quantitative ownership evidence
│  module: Example.mon
│  theorem: certified definitions satisfy typed ownership ANF
├─ definition identity @ 2:3
│  ├─ judgment: Σ ; Ψ | Γ ⊢ℓ identity : A ! ε ▷ Δ
│  ├─ source shape: parameters=1 body-forms=1
│  ├─ typed Core: valid
│  │  ├─ lowering: ok
│  │  └─ binding validation: valid
│  ├─ quantitative signature: graded=1 erased=0
│  │  └─ canonical runtime types=1
│  ├─ ownership ANF: valid blocks=1 instructions=1
│  │  └─ lowering obligation: valid
│  ├─ certificate check: valid
│  │  └─ resource/control-flow obligations: discharged
│  └─ verdict: VERIFIED — safe for certified QTT consumers
└─ module verdict: VERIFIED
[qtt] pipeline: verified=1 unsupported=0 internal=0 module=Example.mon
#+end_example

The tree deliberately says “evidence,” not “mechanized proof.”  =VERIFIED=
means the currently implemented executable Core/ANF certificate checks
succeeded for the accepted fragment.  =UNSUPPORTED= names the first undischarged
stage and promises that conservative code generation remains in force.
=INTERNAL ERROR= rejects the certificate.  The final one-line record is stable,
ASCII-only CI output; the tree is the explanatory witness for humans.

The detailed tree follows the shape of the retained artifacts rather than a
flat sequence of pass messages.  A function expands into its formal contexts,
then binder contracts, result contract, and finally the block graph:

#+begin_example
├─ definition identity @ 2:3
│  ├─ judgment: Σ ; Ψ | Γ ⊢ℓ identity : A ! ε ▷ Δ
│  ├─ typing contexts
│  │  ├─ Σ global signature: module=#…
│  │  ├─ Ψ modal/meta context: layer=0 staged-binders=0
│  │  └─ Γ quantitative context: binders=1
│  ├─ binder contracts
│  │  └─ value #1
│  │     ├─ quantity: ρ_allowed=1 ρ_observed=1
│  │     │  └─ subusage proof: 1 ≤ 1  ✓
│  │     ├─ demand derivation
│  │     │  └─ Var [ρˢ=1 ρʳ=1]
│  │     ├─ ownership: consumed
│  │     ├─ representation: immediate
│  │     └─ canonical type: #…
│  ├─ result contract
│  │  ├─ capability: immediate
│  │  ├─ provenance: immediate
│  │  ├─ representation: immediate
│  │  ├─ canonical type: #…
│  │  └─ contract digest: #…
│  ├─ ownership ANF: valid blocks=1 instructions=1
│  │  └─ block b0 (φ-parameters=0)
│  │     ├─ op i0: move  %v1 ← κ#1  [Γ,κ ⇒ Γ]
│  │     └─ terminator: return %v1
#+end_example

Here =ρ= is a usage quantity, =ω= is printed for unrestricted usage, =≤= is
the actual subusage obligation, =φ= marks SSA block parameters, =∅= denotes an
empty context, and =✓= appears only beside a discharged executable check.
Binder, type, module, and contract identities are printed in their canonical
domains so provenance can be followed between stages.  ANF blocks retain source
order and nest their operations under their real control-flow parent; branches
therefore look like branches when skimming the output.

Every binder additionally retains its checked demand derivation. =ρˢ= counts
syntactic occurrences, while =ρʳ= is the path-sensitive runtime demand consumed
by the graded signature. The renderer uses the actual =Zero=, =Var=, =Let=,
=If=, =Sequence=, =Apply=, =Lambda=, and =Write= rules and recursively prints
their premises. A choice therefore exposes both its algebra and proof shape:

#+begin_example
├─ portable certificate: valid-after-Core-free ✓
└─ If core=#7e35f60d17866ced [ρˢ=2 ρʳ=1]
   ├─ choice equation: ρʳ = ρc + (ρt ⊔ ρe)
   ├─ condition: Zero core=#70824cfed1805ee1 [ρˢ=0 ρʳ=0]
   ├─ then: Var core=#06dba336102f4979 [ρˢ=1 ρʳ=1]
   └─ else: Var core=#7f3555aa9dd0d354 [ρˢ=1 ρʳ=1]
#+end_example

This makes the important distinction visible: two mutually exclusive uses
contribute two syntactic occurrences but runtime choice joins them with =⊔=,
producing demand one. Sequence nodes instead display
=ρʳ = Σᵢ ρᵢ=. These trees are immutable snapshots of independently checkable
=QttDemandDerivation= values, not explanations reconstructed from the final
number. Each =core=# identity combines the live Core node's structural
fingerprint, the demand subject, and its path through the derivation. The path
qualification deliberately distinguishes structurally identical occurrences
in different branches.

The snapshot also retains the minimal rule witnesses needed to recompute both
=ρˢ= and =ρʳ=: local use, binding/parameter scope, direct-application arity,
and the boundary between syntactic and latent premises. The portable checker in
=qtt/evidence.c= runs after the borrowed typed-Core tree has been freed and
rejects missing identities, malformed premise shapes, or altered quantities.
Thus =valid-after-Core-free ✓= is an executable arithmetic and proof-shape
check, not merely a rendering label. It is intentionally not a cryptographic
attestation or a mechanized metatheoretic proof; the original live-Core demand
checker remains responsible for source correspondence.

Operations use =%vN= for SSA values and =κ#N= for ownership capabilities.
Resource-changing instructions show their abstract context transition:
=Γ ⇒ Γ ⊎ {κ}= allocates, =Γ,κ ⇒ Γ,κ= preserves a borrowed capability, and
=Γ,κ ⇒ Γ= consumes one by move or drop.  These are rule labels for the printed
operation, while the independent ANF verifier remains authoritative for the
concrete block state.

Control flow retains φ-parameters and both edge-argument vectors:

#+begin_example
│  │  ├─ block b0 (φ-parameters=1)
│  │  │  ├─ φ(%v0)
│  │  │  ├─ op i0: const-bool  %v1 ← literal
│  │  │  └─ terminator: branch %v1
│  │  │     ├─ then ⇒ b1(%v0)
│  │  │     └─ else ⇒ b2(%v0)
│  │  ├─ block b1 (φ-parameters=1)
│  │  │  └─ terminator: jump
│  │  │     └─ edge ⇒ b3(%v2, %v0)
#+end_example

Thus =⇒= has two visually distinct but related uses: inside brackets it denotes
a capability-context transition; on a control edge it denotes transfer to a
specific block with the displayed SSA arguments.  The surrounding labels make
the domain unambiguous.

The renderer consumes =QttShadowEvidence=, an owned snapshot collected before
the signature and ANF artifacts are freed.  It does not rerun inference or
guess ownership from parameter spelling.  =qtt_shadow_evidence_free= is the
single cleanup boundary for its parameter and block detail arrays.

Every error enum printed by this boundary has a symbolic name.  Numeric-only
diagnostics are not acceptable here because they cannot be followed without
reading compiler headers.  Each definition tree is flushed atomically enough
for concurrent imported-module compilers, preventing interleaved processes from
splitting UTF-8 proof-tree edges.

Regression contract: =tests/test_qtt_compiler.py= checks both a successful
identity certificate and a named unsupported global-call lowering, including
the conservative fallback and partial module conclusion.

*** Terminal presentation contract

Interactive evidence trees use a restrained semantic palette:

- bold cyan for the QTT evidence heading and cyan for definition identity;
- magenta for the formal judgment and theorem being checked;
- green for reached and discharged obligations;
- bold green for =VERIFIED=;
- yellow for unsupported boundaries and conservative fallback;
- bold yellow for =UNSUPPORTED= and =PARTIAL=;
- red for rejected obligations and bold red for =INTERNAL ERROR=; and
- dim text for source coordinates, pending stages, and explanatory obligation
  labels.

Color is automatic only when standard output is a terminal. Redirected logs,
compiler harnesses, and CI therefore retain the exact plain-text tree and never
receive escape sequences. =NO_COLOR= disables automatic styling. The
=MONAD_QTT_COLOR= setting accepts =always=/=1=/=yes= and
=never=/=0=/=no=; an explicit setting takes precedence over automatic terminal
detection and permits deterministic terminal snapshots.

Styling is deliberately orthogonal to evidence. Removing every ANSI sequence
must leave the same words, tree structure, status names, and compiler decision.
The final =[qtt] pipeline:= record remains unstyled even on a terminal so tools
can consume it without stripping presentation codes.

** Current maturity

These percentages are calibrated engineering estimates, not theorem coverage
or lines-of-code ratios. A score means:

- =0–10%= vocabulary, design notes, or isolated experiments;
- =10–30%= executable kernel with important architectural gaps;
- =30–60%= coherent subsystem covering a useful restricted fragment;
- =60–80%= broad implementation with named unsupported boundaries;
- =80–95%= production-capable with strong formal and integration evidence;
- =95–100%= the intended language-wide claim, including mechanized metatheory
  and authoritative code generation.

The score is deliberately multidimensional. Excellent ownership ANF cannot
compensate for absent dependent erasure, and a mechanized grade algebra would

Using those weights gives a literature-QTT maturity near =62%=. Reasonable
uncertainty is about ±4 points because “state of the art” weights dependent
typing, practical inference, and mechanization differently.

For the narrower goal “QTT-informed deterministic automatic memory
management,” the current estimate is =80–86%=. That score is higher because the
ownership calculus, resource evaluation, calls, and reclamation planning are
substantial even though graded dependent elaboration is young.

Claims this score does *not* authorize:

- that Monad currently implements Idris 2-style QTT;
- that every zero-use source value is erased;
- that all accepted Monad programs are leak- or use-after-free-safe;
- that recursive, exceptional, concurrent, or foreign code is reclaimed
  statically;
- that proof evidence can yet be erased from release binaries by theorem; or
- that production LLVM generally follows ownership ANF (only the documented
  evidence-gated lexical String, flat layout-literal, and owned-result call
  fragments do).

The maturity estimate should be updated only when a dimension crosses a stated
exit criterion with executable regression evidence. Adding syntax, data
fields, or documentation alone does not increase it.

The critical path is =A → B → C → D/E → F → G=. Small production slices remain
useful, but Phase B is now the highest-leverage theory work.

* Status

This document specifies the fragment implemented by =qtt/=; it is not a
soundness claim for the complete Monad language. Unsupported source constructs
must remain outside the verified fragment.

The design separates three facts which must not be conflated:

1. *Quantitative demand* describes how often a binding can be evaluated.
2. *Ownership capability* describes who may move or destroy storage.
3. *Representation* describes whether a value has storage requiring a
   destructor.

This separation follows quantitative typing rather than treating heap
allocation as an intrinsic property of every linear value.

The target integrated elaboration judgment is:

#+begin_example
𝒮 ; Ψ | Γ ; Ω ⊢ℓ e : A ! ε ▷ Ω′
#+end_example

Here =𝒮= is the global signature, =Ψ= the layered meta-context, =Γ= the
quantitative lexical typing context, and =Ω= the input capability/provenance
context. Checking =e= at layer =ℓ= synthesizes type =A= and inferred effect
=ε= while transforming resources to =Ω′=. This is a stable architectural
target, not one monolithic implementation API: formation, subusage, effect
inclusion, modal transition, provenance, erasure, and lowering remain
subsidiary judgments.

Place-indexed effects and loan authority share the canonical place vocabulary
from =qtt/place.h=. A place is a qualified root plus a bounded path of
type-checked, one-based layout-field ordinals. The empty path denotes the whole
root; paths overlap exactly when either is a prefix of the other, while sibling
paths are disjoint. Effect labels preserve this structure, for example
=write:module:binder:1.2=. Legacy opaque projections remain conservative when
mixed with structural paths. Dynamic indices, unions, and unbounded path tries
remain future work.

The Resource verifier stores the exact place in every active loan. Exclusive
loans conflict only with overlapping places, so two statically certified
sibling fields can be mutated simultaneously. Loan closure and writes must
cite the identical place and loan kind. Whole-root reads, moves, drops,
duplication, and rehoming overlap every outstanding field loan. A projected
move through an exact exclusive alias now evacuates that field in the
capability state while leaving certified sibling projections usable.
Whole-root reads, moves, duplication, rehoming, and replacement reject a
partial aggregate. Final root drop is backed by a destructor-bound mask
certificate: paths must traverse the structural drop plan, be canonical and
pairwise prefix-disjoint, and match the qualified root. Masked execution skips
exactly those evacuated subtrees while reclaiming the remaining siblings and
aggregate shells. Branch joins require equal
evacuation masks, so moving a field along only one arm is rejected. The heap
evaluator reports projected moves separately from whole-owner escapes, and
the effect bridge labels evacuation as =Write(place)=. Semantic IR derives the
certificate from the verified Resource IR, owns it, and independently
reconstructs it during verification; a merely well-formed but unrelated mask
is rejected. Production LLVM accepts empty masks and fails
closed on projected masks until structural projected cleanup is lowered.
Root replacement remains a distinct transition: it destroys the displaced
payload while the binding itself stays live or later moves out. It therefore
requires the verified destructor descriptor and a Resource proof that the root
is not partial, but does not require a final-drop mask for that binding.

Resolved dotted source symbols now lower through a typed lexical environment.
Every component is checked against the enclosing layout and becomes a
canonical =QTT_CORE_PLACE= prefix. A tail use of an owned field lowers to the
direct =MOVE_PLACE= Resource transition: unique ownership of the root is its
authority, outstanding overlapping loans are rejected, and the aggregate root
remains live but partial until its masked drop. This path reaches verified
Semantic IR and produces the corresponding non-empty mask from ordinary source
AST. Ownership ANF and production LLVM do not yet lower =QTT_CORE_PLACE=, so
the compiler remains fail-closed at that next boundary.

Semantic IR copies the place into each capability-transition certificate and
independently compares it against Resource IR during verification. Resource
access evidence can also derive the same canonical place-qualified label used
by effect rows. Exclusive-loan acquisition is authority, not mutation, so only
an actual write-through-exclusive-alias produces a =write:= effect.

Root-variable =set!= now lowers to an explicit Typed-Core write carrying a
canonical place and value subtree. Core validation requires the target binder
to be in scope. Both the proof-tree demand judgment and the independently
implemented symbolic usage producer count one target use plus the value's
demand. Semantic IR records the exact place, assigns the canonical singleton
=write:module:binder:0= effect row, and rejects forged place or effect
evidence.

The Resource-plan boundary distinguishes storage mutation from ownership
replacement. Immediate and inline lexical writes are accepted because they do
not replace an owned heap capability. An owned root write instead elaborates
to the atomic transition

#+begin_example
Ω, κ : owned A  ── REPLACE(κ, v : fresh A) ──▶  Ω, κ : owned A
#+end_example

The resource identity remains live, but the old payload is destroyed before
the fresh payload is installed. The independent verifier requires an exact
root place, a direct owner rather than an alias, equal owned-heap
representation, fresh allocation evidence for the replacement, and no
overlapping active loan. The abstract heap evaluator counts one destruction
and one allocation while preserving one live owner and a peak of one. This is
deliberately one indivisible transition: spelling it as a drop followed by an
allocation would create a capability gap and make exceptional or branching
extensions harder to state correctly.

Ownership ANF now declares each mutable place with its value type and lowers a
straight-line write to an explicit =WRITE_PLACE(place, operand) -> result=
instruction.  The ordinary ANF verifier independently requires a declared
nonzero place, a defined operand of the declared type, and a fresh typed SSA
result.  Lowering installs that result as the binding's new SSA version, so a
later read observes the written value.  Immediate and inline parameters remain
ordinary SSA values even when their quantitative mode is shared; only
borrowed/shared owned-heap parameters require non-owning entry capabilities.

For the currently certified literal fragment, an owned-root write lowers to
=REPLACE(resource, root-place, owned-heap, operand) -> result=. The ordinary
ANF verifier checks resource liveness, the declaration's structural type and
representation, the root place, and SSA freshness. Its evaluator replaces the
payload and accounts for the old destruction and new allocation. Semantic IR
records the corresponding =OWNED -> OWNED= transition; the Semantic-IR/ANF
correspondence theorem matches its ordinal, control path, representation,
resource identity, and exact place. A forged replacement can therefore be
internally consistent in neither layer nor smuggled between them.

The Semantic-IR/ANF correspondence checker independently reconstructs the
ordered write obligations from Typed Core and requires each immediate/inline
=WRITE_PLACE= or owned =REPLACE=, place, representation, resource, declaration,
and type to match exactly. Forging both an ordinary write declaration and
instruction therefore still fails correspondence even when the ordinary ANF
verifier accepts the internally consistent forgery. Source =begin= lowers to a
real Core sequence, so a compiled function containing
=(begin (set! x 2) x)= reaches this verified ANF fragment and retains its
ordinary runtime behavior.

Ownership ANF also carries lexical SSA state explicitly across control flow.
Each branch edge supplies typed arguments for the lexical versions visible at
the branch entry; each arm receives fresh block parameters; and the join
receives the version produced by each arm.  This is the block-argument form of
SSA φ nodes.  It handles symmetric writes and the important asymmetric case
where one arm writes while the other forwards its incoming version.  The
ordinary verifier checks both branch argument vectors independently, including
arity, definition, and type, while the evaluator binds only the selected
edge's arguments.  Semantic-IR/ANF correspondence accepts branch-local writes
only after those ordinary CFG checks succeed.

This is not yet a language-wide source-mutation claim. The registered compiler
pipeline verifies and executes source String replacement, but the early
pre-inference proof-tree pass can conservatively report that same definition
as unsupported because the literal types are not attached yet.

Production LLVM now consumes a separate backend replacement certificate for
the literal String fragment. That certificate is reconstructed from verified
Semantic IR and binds the exact resource, root place, representation,
destructor descriptor, source binding, and materialization policy. Code
generation duplicates static initializer/replacement literals into owned
storage and emits, in order:

#+begin_example
new = strdup(replacement)
old = load(owner-slot)
free(old)
store(new, owner-slot)
#+end_example

Returning the new generation transfers it without a final free; a dead new
generation is reclaimed by the existing verified scope-exit cleanup. Repeated
replacement consumes one ordered certificate per write. Replacement
certificates are collected recursively in the same structural order consumed
by source code generation, so each conditional leaf destroys only the
generation live on that path. Symmetric, asymmetric, and nested branches are
checked both in emitted LLVM and by executing every distinct replacement arm.
Disabling QTT memory or replacing from an uncertified borrowed alias emits
neither copies nor frees, retaining conservative legacy behavior.

The production source pipeline now certifies symmetric =set!= operations
nested directly in =if=
arms, including the path-sensitive demand judgment, place declaration,
branch-local =WRITE_PLACE= instructions, SSA versions, join arguments, and
ordinary execution. The integration treats prelude =Bool= as its checked
closed finite set and recovers a missing variable-node annotation only from
the already-typed lexical binding; it does not guess a type from syntax.
Asymmetric and nested branch-write shapes now have direct source-pipeline,
LLVM-structure, and runtime regressions in addition to Core/ANF coverage.
Typed immediate and inline free variables (such as an enclosing Bool branch
condition) may be embedded in Resource IR without manufacturing an owned
capability; unknown or owned free variables still fail closed. Dotted layout
lvalues need canonical typed projection paths from layout metadata.
Replacement calls returning fresh owned Strings are now certified from the
canonical callable result contract. Their result transfers directly into the
owner slot without copying; LLVM materializes the call result before freeing
the displaced generation, and a representation-direct runtime observation
proves the returned allocation remains live. The probe also exposed a
separate presentation seam: direct =show= of a returned raw String can lose
its nominal representation because the current core additionally introduces
=String= as a =[Char]= refinement. This does not invalidate the raw call ABI
or ownership transition, but nominal refinement/codegen type preservation
must be unified before using =show= as an ABI oracle. Projected writes and
partial-initialization masks remain separate work.

* Grades

The solved scalar grade domain is

  =R = ℕ ∪ {ω}=

with saturating addition and multiplication. The present Core derivation also
records an explicit control-flow choice:

  =choice(r, s) = max(r, s)=

for a single exclusive conditional execution. This =max= interpretation is a
runtime upper demand, not a general replacement for additive QTT. Syntactic
occurrences are retained separately because compiler lowering materializes
both branch bodies.

For each Core expression =e= and BinderId =x=, a derivation proves:

  =e ⊢ x ⇝ (s, r)=

where =s= is the number of syntactic occurrences and =r= is the maximum demand
on one execution path in the currently pure, terminating, acyclic fragment.

* Demand rules

** Variables

  =x ⊢ x ⇝ (1, 1)=

  =y ⊢ x ⇝ (0, 0)= when =x ≠ y=

** Values and globals

  =v ⊢ x ⇝ (0, 0)=

** Sequential composition

If =e₁ ⊢ x ⇝ (s₁,r₁)= and =e₂ ⊢ x ⇝ (s₂,r₂)=, then:

  =e₁ ; e₂ ⊢ x ⇝ (s₁+s₂, r₁+r₂)=

Let and application currently use the same sequential combination over their
premises.

** Exclusive conditionals

If condition and arms derive =(s_c,r_c)=, =(s_t,r_t)=, and =(s_f,r_f)=:

  =if c t f ⊢ x ⇝ (s_c+s_t+s_f, r_c+max(r_t,r_f))=

The proof object retains all three premises. A bottom-up checker independently
reconstructs the required rule, source node, BinderId, premise structure, and
both grades.

** Lambdas

For =λx.e=, remove the parameter BinderIds from =U(e)=. The remaining support
is captured once when the closure is constructed:

  =C(λx.e)(y) = 1= when =U(e)(y) ≠ 0=

The unmodified remaining grade is retained as latent per-invocation demand:

  =L(λx.e)(y) = U(e)(y)=

Invoking the closure =k= times contributes =k · L(λx.e)=. The source traversal
exports =C= for nested construction and retains =L= under the nested lambda's
=(ModuleId, ClosureId)=. Full direct factory calls now instantiate existential
slot environments and invocation substitutes parameter, local, and expression
origins. Lexical aliases now retain that evidence. Propagating environments
through function-valued parameters, data structures, module interfaces, and
ownership ANF is the next
higher-order integration boundary.

* Function contracts

A checked function contract has the form:

  =Σ(f) = (xᵢ : τᵢ @ ρᵢ [qᵢ,mᵢ]) → (τ @ ρ [o])=

where:

- =qᵢ= is checked runtime demand;
- =mᵢ= is erased, borrowed, consumed, or shared;
- =ρᵢ= is the runtime representation;
- =o= is immediate, owned, borrowed, shared, or unknown result ownership.

Real post-inference Core stores =τᵢ= explicitly by decomposing the zonked arrow
type. Occurrence-based recovery exists only for manually constructed legacy
test Core and is not part of the intended calculus.

* Ownership judgment

ANF verification maintains:

- =Δ=: SSA value types;
- =Γ=: live owned capabilities.

A move requires =x ∈ Γ= and produces =Γ \\ {x}=.
A drop requires =x ∈ Γ= and produces =Γ \\ {x}=.
A borrow requires =x ∈ Γ= and preserves =Γ=.
Every return requires =Γ = ∅= for local and consumed-entry capabilities.
Every control-flow join requires predecessor ownership contexts to agree.

This proves absence of leaked or multiply consumed capabilities in the accepted
ANF fragment. The Resource IR additionally verifies exact lexical loan scopes,
overlap conflicts, and branch-equivalent outstanding-loan contexts. It does
not yet prove absence of dangling borrows language-wide: borrowed results,
escaping closures, loops, exceptions, and source-level mutation are not yet
represented by the authoritative loan judgment.

* Module signatures and calls

A callable identity is the triple =(module, fingerprint(name), name)=. The
fingerprint is an index only: equality also compares the complete name, so a
hash collision cannot alias two declarations. A module signature environment
maps these identities to canonical function contracts.

An ownership call has the judgment:

  =Σ(f) = (τᵢ @ ρᵢ [mᵢ]) → τ @ ρ [o]=
  =Δ; Γ ⊢ call f(vᵢ) : τ; Γ'=

The executable checker requires every =vᵢ= to have the canonical TypeId,
primitive ANF type, representation, and transfer prescribed by =Σ(f)=.
Consumed operands must be produced by an explicit =move=; borrowed operands
must be produced by an explicit =borrow=. An owned result extends =Γ'= with a
fresh capability, which subsequent ANF must move or drop exactly once.

Transfer is representation-aware. Quantitative consumption of an immediate,
inline, or foreign value is ordinary =VALUE= transfer; only an =OWNED_HEAP=
capability can require =MOVE= or =BORROW=. Planning, lowering, and verification
share this single rule.

Canonical signatures also carry a structural contract fingerprint covering
parameter/result TypeIds, grades, observed demands, ownership modes, and
representations. Every named ANF call cites that fingerprint. Verification
recomputes it from the resolved signature and still checks every structural
field, so the fingerprint is compact stale-contract evidence rather than a
hash-as-equality shortcut.

Module checking is two phase. It first collects and canonicalizes every
contract, then solves the currently supported interprocedural tail-transfer
constraints before checking bodies. Quantitative demand uses least solutions,
but unique *must-transfer* is coinductive. For the finite candidate set =C=,
define

  =F(S) = { p ∈ C | every tail path returns p or transfers p to q ∈ S }=.

The solver computes the greatest fixed point =νF= by descending iteration from
=C=. Conditional paths use conjunction: one retaining alternative removes the
candidate, and that removal propagates around its recursive cycle. A closed
mutually tail-recursive cycle can therefore certify that one unique capability
is handed from activation to activation without requiring an arbitrary base
seed. The emitted certificate records candidate, proven, rejected, and
iteration counts; allocation failure is explicit incomplete evidence.

This removes declaration-order dependence and proves capability conservation
for the accepted tail-recursive call fragment. It does *not* prove termination,
bounded stack use, or bounded allocation during divergence. Non-tail recursion,
locals live across recursive calls, loops, effects, exceptions, and recursive
heap structures still require stronger resource invariants.

The fixed point refreshes structural contract fingerprints after ownership
modes change. Each definition is then checked through environment-aware
Semantic IR before ownership ANF. Named-call quantitative usage scales an
argument context by the resolved parameter's observed grade; it is not
approximated as one use. Semantic call evidence records the resolved callable,
contract fingerprint, argument TypeIds and representations, transfer modes,
source Core variables, result contract, call ordinal, and exact nested control
path. This evidence is independently reconstructed during verification.

ANF call operands separately name the capability that produced a moved or
borrowed SSA value. The verifier tracks resource provenance for every
=move=/=borrow= result and requires the cited source to match. Named lowering
reuses an argument's existing move when possible instead of manufacturing a
synthetic bind/move chain.

The source compiler establishes the same-module signature environment =Σ=
before checking any definition body. Named source calls therefore lower
against the exact canonical contract later consumed by code generation rather
than an empty shadow environment. A call returning =owned/fresh= introduces a
fresh ANF capability; binding an otherwise-unused result moves that capability
to the lexical binder and emits its checked drop. Source Core may omit a
redundant primitive annotation or retain a literal's pre-coercion type at this
boundary: the resolved canonical parameter/result TypeIds and their structural
witnesses are authoritative after elaboration.

The module pipeline now directly checks Semantic-call-to-ANF correspondence.
Calls are paired by explicit call ordinal, never block storage order. The
checker requires equal control paths, callable and contract identities,
argument TypeIds/representations/transfers, source capability provenance, and
result contracts. An owned result must name a concrete fresh ANF capability,
whose linear discharge is checked by ordinary ANF verification. Conditional
calls on distinct arms retain distinct path evidence even when they share a
source capability.

* Current metatheoretic claims

The implementation currently supports the following checkable claims:

1. Demand proof integrity: changing a rule, premise, source, BinderId, or grade
   makes the independent checker reject the derivation.
2. Path-sensitive function demand: mutually exclusive branch demands combine
   by maximum while structural lowering retains the summed occurrence count.
3. Capability conservation: verified acyclic ANF consumes every owned entry
   and local capability exactly once along every represented return path.
4. Checked direct transfer: a consumed direct-call argument moves from caller
   ownership into a fresh callee capability, which the callee must discharge.
5. Checked named transfer: a named call resolved through the module environment
   obeys the same canonical type, representation, provenance, and capability
   conservation checks as an inlined direct call.

These are implementation theorems for a checked finite representation, not
machine-checked preservation or progress theorems.

* Proof-carrying policy

The compiler should carry evidence, but not every representation should carry
the same amount:

1. *Elaboration and checking* may retain full derivation trees, source
   identities, premises, and diagnostic structure.
2. *Compiler IR* should carry compact checked certificates: canonical type and
   signature IDs, quantitative grades, ownership modes, representation and
   destructor IDs, plus a digest binding the evidence to its source.
3. *Object files and module interfaces* should serialize only the contracts
   required for separate compilation and rechecking.
4. *Release executables* need not contain proofs after verified lowering unless
   audit, proof-carrying-code, or independently checkable deployment is
   explicitly requested.

Erasing proof evidence after checking is sound only after a mechanized erasure
and lowering theorem exists. Until then, the shadow pipeline retains enough
source identity to recheck its executable certificates.

* Canonical type evidence

Zonked structural types are interned in a compilation-local arena. Each
canonical =TypeId= denotes one structural equivalence class. A structural
fingerprint accelerates lookup but is not equality evidence: entries with the
same fingerprint are compared structurally and remain distinct if their
structures differ.

Function parameter and result contracts carry canonical IDs after
canonicalization. Call checking requires both matching IDs and coherent
borrowed structural metadata. Raw pointers remain available for the legacy
compiler, but they are not the identity used by checked contracts.

* Required before a language-wide soundness claim

- A formal dynamic semantics for Core and ownership ANF.
- Preservation of types, grades, and ownership under lowering and evaluation.
- Progress or a precisely delimited partiality/effect theorem.
- Loan regions and non-escaping borrowed results.
- Resource invariants for recursive call graphs and loops (signature transfer
  constraints now have a finite least-fixed-point solver).
- Effects, mutation, exceptions, concurrency, and foreign calls.
- Canonical type, signature, representation, and destructor identities.
- Mechanization in a proof assistant or equivalently strong independent model.
- A verified connection from ANF destruction to emitted LLVM behavior.

* Cycle 61: exact lexical code aliases

The first indirect-call ownership slice is deliberately intensional and
finite.  A =let= binding may denote a statically known, capture-free lambda;
further lexical aliases preserve that exact lambda identity by =BinderId=.
Calling any such alias derives the same parameter transfer decision as calling
the lambda directly.  Capture-free code is represented as =INLINE= proof data:
it neither allocates a closure capability nor emits a fictional drop.

Two independent executable judgments now agree on this fragment:

- resource elaboration emits argument borrows or moves from the lambda's
  tail-transfer behavior, and structural replay reconstructs the alias chain;
- ownership ANF resolves the exact code value and lowers through the existing
  checked direct-call path.

The regression in =tests/test_qtt_indirect_call.py= includes a two-link alias,
an owned string transfer, sanitizer execution, resource-plan replay, ANF
verification, and a negative function-parameter case.  An arbitrary function
parameter is still rejected: no callable contract is guessed from its arrow
type.

This is not yet general higher-order ownership.  The canonical symbolic-usage
judgment still needs its own lexical callable environment before Semantic IR
can certify variable callees.  Capturing closures additionally require an
environment representation, field ownership, and invocation contract.  The
next consolidation step is therefore to move exact callable resolution into a
shared lexical environment consumed by usage, resources, Semantic IR, and ANF,
rather than duplicating increasingly broad resolver logic.

* Cycle 62: lexical callable evidence enters Semantic IR

Exact callable identity now has a shared immutable lexical environment in
=callable_env.h=.  A binding maps one module-qualified =BinderId= to one known,
capture-free lambda; aliases resolve transitively without using source names.
The shared predicate for capture freedom is consumed by symbolic usage,
resource elaboration, and ownership ANF.

Symbolic usage distinguishes two facts that must not be conflated:

  =callee source demand ⊗ resolved lambda invocation grade=.

The original variable expression contributes its ordinary occurrence, while
the resolved lambda supplies parameter-domain grades and latent closure
usage.  Replacing the variable wholesale would incorrectly erase invocation
demand.  =let= extends the callable environment only for its body, preserving
lexical scope and shadowing.

Semantic IR no longer computes every node as a context-free subtree.  Evidence
construction and independent verification walk the Core tree with the same
lexical extension rule, while each node is still re-lowered into a fresh grade
arena during verification.  The two-link callable-alias regression now passes
whole-tree usage lowering, resource-plan replay, Semantic IR verification, and
ownership ANF verification; an unconstrained function parameter remains an
explicit unsupported application boundary.

The source compiler probe also exposed two Core-lowering bugs.  Annotated local
lambdas can now recover parameter types from their syntax when legacy inferred
arrow metadata is unavailable, and a sequence takes the type of its last
expression instead of the type of the enclosing lambda.  Consequently this
source form reaches valid typed Core rather than an internal error.

Production source ownership ANF still conservatively rejects this form, and
legacy fallback code generation does not yet execute its returned String
correctly.  Therefore no end-to-end reclamation claim is made for lexical
callables yet.  The next cycle must connect the compiler's source-shaped body
normalization to the already verified Core fragment and then require correct
execution and LLVM destruction evidence before upgrading the claim.

* Cycle 63: source lexical callables become verified programs

The capture-free lexical callable fragment now crosses the real compiler
boundary.  A source program may bind an annotated lambda, alias that binding
transitively, move an owned =String= through the final alias, return it, and
receive a =VERIFIED= module judgment.  The compiled executable is part of the
regression contract, not merely the shadow proof harness.

The missing invariant was typed-Core completeness.  Legacy inference can omit
types on self-describing primitive literals and their lexical uses.  Core now
installs stable primitive witnesses for =String=, =Path=, =Char=, =Keyword=,
and =Ratio= literals, while variable nodes recover absent or unknown types from
the lexical type scope.  Thus the production term presented to call planning
is the same typed term used by the standalone ownership tests.

The runtime closure ABI returns a boxed =RuntimeValue=.  Callable aliases must
therefore preserve their source lambda and return contract so code generation
can select the typed unbox operation.  One shared metadata-preservation helper
is used for ordinary definitions and =with= bindings; the metadata survives
=g = f= chains.  For an annotated =String= result the emitted LLVM now contains
an explicit =rt_unbox_string= call before returning from the typed function.

=tests/test_qtt_compiler.py= requires all of the following for the two-link
source program: valid typed Core, valid ownership ANF, a verified verdict, an
explicit ownership move in the proof trace, the typed LLVM unbox, successful
linking, and executable output equal to =owned=.

This proves correct ownership transfer for an escaping result, not automatic
destruction of a discarded higher-order result.  The next higher-order memory
milestone is a non-escaping lexical call whose fresh or transferred result is
materialized with a checked destructor and whose LLVM contains the matching
=free=.  Capturing closures and arbitrary callable parameters remain outside
this exact-code fragment.

* Cycle 64: discarded exact-call results enter ownership ANF

A zero-use binding of a two-link lexical callable result now has an explicit
linear discharge in the production compiler proof.  The source regression
binds =f= to a capture-free =String -> String= identity, aliases it as =g=,
moves an owned literal through =(g payload)=, binds the result as =ignored=,
and returns an immediate integer.  Its trace must contain =alloc κ#ignored=
followed by =drop κ#ignored=, and the independently checked ANF certificate
must remain =VERIFIED=.

The bug was a semantic-boundary disagreement.  Legacy AST metadata can retain
the type of a callable while typed Core has already recovered the callable's
lexical arrow contract.  Application lowering now projects its result through
that recovered arrow, and lexical variable types prefer the binder-indexed
type scope over stale occurrence annotations.  Ownership ANF additionally
derives an exact lexical call's result representation from the resolved
capture-free lambda signature.  Consequently an unused owned result is no
longer mistaken for inline code and silently omitted from the resource state.

=tests/test_qtt_compiler.py= checks the source program from parsing through
typed Core, ownership ANF, certificate verification, LLVM generation, linking,
and execution.  =tests/test_qtt_indirect_call.py= continues to check the same
alias semantics independently with a sanitizer-enabled hand-built Core model.

This cycle proves logical reclamation placement, not physical reclamation for
the transferred alias result.  The backend cleanup interface still couples
materialization and final destruction within one lexical source scope.  Here
the literal is materialized in an outer scope, transferred through the exact
call, and dropped by an inner binder.  The next cycle must introduce a
binder-keyed materialization/destruction plan spanning those scopes, then
require the generated LLVM to contain exactly one allocation and one matching
=free=.  Emitting =free= before that correspondence is checked would turn a
valid ANF proof into an invalid backend claim.

* Cycle 65: binder-keyed cross-scope LLVM reclamation

The discarded exact-call program now crosses the physical memory boundary.
Its outer =payload= binder is materialized exactly once with =strdup=, the
owned pointer is transferred through the capture-free identity and its alias,
and the inner zero-use =ignored= binder emits exactly one LLVM =free=.  The
compiled executable remains part of the proof obligation and returns =64=.

The backend no longer tries to rediscover this fact independently inside each
nested =with=.  Such a scope has already lost the lexical evidence that =g=
resolves to =f= and that =f= is an exact lambda.  Instead, the outer ownership
root constructs one immutable lifetime plan and code generation carries it
through its nested scopes.  Entries are addressed by module-qualified
=BinderId=, never source names or local binding positions:

  - =payload=: =static-copy=, =destroy=no=;
  - =ignored=: =owned-result=, =destroy=yes=.

The plan is accepted only when typed Core, Semantic IR, and ownership ANF all
verify.  Semantic IR supplies the canonical owned-leaf destructor identity;
verified ANF is authoritative for the final =DROP= because the older resource
plan does not yet represent this exact-call result discharge.  When stale AST
type metadata prevents Semantic IR from constructing that leaf descriptor,
the verified ANF allocation operand must independently carry
=QTT_ANF_TYPE_STRING= before the backend may derive the canonical String
destructor.  Unsupported or ambiguous cases still fall back conservatively.

This cross-scope path is deliberately enabled only when the plan contains a
destroyed call result.  Ordinary same-scope dead literals retain the existing
cleanup certifier and its reverse lexical destruction order; escaping literals
retain conservative legacy materialization.  This prevents the new mechanism
from silently changing established ownership behavior outside its theorem.

=tests/test_qtt_compiler.py= now requires the two lifetime-plan entries, the
verified ANF =drop=, exactly one =strdup=, exactly one =free=, successful
linking, and successful execution.  The 23 production-memory regressions guard
same-scope destruction order, moved values, partial moves, mutation, layouts,
and the disabled-memory policy.

The remaining higher-order gap is capturing closures.  Their environment
fields require an explicit structural lifetime plan and a call contract that
distinguishes moving a field out from borrowing it.  Arbitrary callable
parameters likewise remain unsupported until their interface carries a
serialized quantitative transfer and result-ownership contract.

* Cycle 66: unique capturing calls cross the reclamation boundary

The first source-level capturing closure now participates in verified physical
reclamation.  A lexical =payload : String= is captured by an immediately
applied unique lambda, moved out as the call result, bound to an unused
=ignored= result, and destroyed.  The compiler trace exposes the complete ANF
chain: literal, owned allocation, ordinary argument evaluation, capture move,
result allocation, and final drop.  Generated LLVM contains exactly one
=strdup= and one matching =free=, and the linked program executes successfully.

This cycle removed three disagreements between overlapping proof paths:

  - Direct-lambda calls now validate arguments with the same canonical
    parameter =TypeId= contracts as named calls.
  - Every direct-call parameter enters the lexical ANF environment.  Only an
    owned consumed parameter creates a capability binding; immediate value
    parameters remain ordinary SSA aliases.
  - Semantic IR verification now treats destructor evidence as a projection
    of an existing resource certificate.  When the older resource elaborator
    conservatively reports capturing closures as unsupported, the destructor
    table must be empty, while closure fields, grades, effects, call evidence,
    and tree structure remain independently verifiable.

The lifetime backend consequently accepts a conjunction of two independently
checked certificates: verified Semantic IR for the higher-order structure and
verified ownership ANF for the actual alloc/move/drop path.  A legacy resource
certificate contributes destructor evidence when present, but its documented
unsupported state no longer vetoes the stronger path.  For this exact owned
=String= fragment, the verified ANF allocation type derives the canonical
owned-leaf destructor.

=tests/test_qtt_compiler.py= is the end-to-end regression: source parsing,
typed Core, ownership ANF, =VERIFIED= judgment, explicit drop, LLVM allocation
and free counts, linking, and execution.  The Semantic IR/ANF suites and all 23
production-memory tests remain green.

This is unique immediate closure application, not general closure-environment
reclamation.  Stored or returned closures still require code generation to
consume the existing structural field descriptors, allocate an environment
according to unique/shared policy, move or release each capture at its proven
exit, and destroy the environment itself.  Erased direct-call parameters also
need a separately specified runtime-arity rule; this cycle intentionally used
an observed immediate argument so capture ownership was tested in isolation.

* Cycle 67: stored unique closure environments are reclaimed

- six seven!!

An exact capturing lambda may now be stored in a lexical binder, invoked once,
and reclaimed after that invocation.  This is the first cycle in which QTT
controls the lifetime of a physical runtime closure rather than only the
payload flowing through its body.

The uniqueness theorem was generalized from syntactic immediate application to
exact lexical storage.  If a lambda is bound to one =BinderId=, that binder has
exactly one occurrence, and the occurrence is the callee of exactly one call,
the closure is unique.  Two calls, returning the closure, passing it as an
argument, aliasing it, an unsupported capture exit, or a live external use of a
capture still classifies the closure as shared.  Both inference and independent
verification recompute this relation; the negative twice-called regression is
part of =tests/test_qtt_closure_policy.py=.

The compiler lifetime certificate accepts a stored closure only when verified
Semantic IR supplies all of the following:

  - unique storage with reason =single-direct-call=;
  - at least one structural closure field;
  - an owned =String= representation and valid owned-leaf descriptor for every
    field;
  - an exit of exactly =MOVE_OUT= or =RELEASE= for every field;
  - a field ordinal representable in the serialized 64-bit evacuation mask.

The backend records the closure binder and the moved-field mask in the same
module-qualified lifetime plan used for cross-scope string reclamation.  At
scope exit it calls =rt_closure_destroy_unique=.  Moved fields retain their
payload but release their heap box; released fields destroy both.  The closure
environment vector, optional name, runtime closure record, and outer runtime
value are then freed.

Physical capture construction now respects the same field decision.  A
certified moved string uses =rt_value_string_take=, transferring the original
pointer into its runtime box without a hidden =strdup=.  Uncertified, released,
and shared captures retain copying behavior.  The redundant heap-allocated
staging vector was also replaced by lexical LLVM storage because
=rt_value_closure= copies that vector synchronously.

=tests/test_qtt_compiler.py= requires valid typed Core and ownership ANF, a
=VERIFIED= verdict, the unique-closure lifetime and reclamation trace, exactly
one source =strdup=, exactly one ownership-taking box, no copying string box,
exactly one result =free=, exactly one unique closure destructor, successful
linking, and executable output =66=.  Closure-policy, closure-plan, Semantic
IR/ANF, compiler integration, and all production-memory tests pass.

This is not shared-closure reclamation.  Escaping, aliased, or repeatedly used
closures require a retain/release or another proved shared-storage discipline.
The current physical theorem is also restricted to at most 64 owned =String=
fields; structural aggregates and wider environments need a serialized drop
mask/descriptor rather than a machine-word mask.  Erased-parameter ABI work
and general callable interface contracts remain separate gaps.

* Cycle 68: representation-sensitive named calls and one diagnostic Σ

Named-call lowering no longer confuses quantitative sharing with a physical
heap loan. A parameter may be inferred =BORROWED= or =SHARED= while represented
as an immediate SSA value; its operational transfer is =VALUE=, so no resource
capability or loan is created. The named path now follows the same
representation-sensitive rule used by direct calls and
=qtt_call_transfer_for_parameter=. Borrowed/shared =OWNED_HEAP= parameters
remain conservative until non-owning entry obligations and call-scoped loan
endpoints are represented explicitly.

The production regression defines =invoke-identity : Int -> Int= as a named
call to a same-module function whose parameter is quantitatively borrowed. It
requires typed Core, a verified ownership-ANF call instruction, four of five
fixture definitions verified, successful LLVM compilation, and runtime output.

The legacy =[qtt-shadow]= diagnostic previously rechecked each definition
without the module signature environment and could report =unsupported= beside
an authoritative =VERIFIED= proof. It now collects evidence with the same
canonical =Σ= environment used by the production source pipeline. This removes
one observable semantic disagreement rather than teaching two implementations
the same special case independently.

* Cycle 69: call-scoped heap loans and non-owning entry capabilities

Ownership ANF now distinguishes a heap resource that a function owns from a
heap resource it may only observe. Each initial resource carries an explicit
=owned= bit. A =CONSUMED= parameter enters with ownership; a =BORROWED= or
=SHARED= parameter enters as a non-owning capability. The verifier permits
that capability to remain live at return, but rejects =move=, =drop=, projected
move, and owned mutation from it.

For a named parameter whose operational transfer is =BORROW=, lowering emits
the interval

#+begin_example
borrow %loan ← &κ
call   %result ← f(%loan)
drop   κ                 ; iff the caller owns κ and this is its last use
#+end_example

The =CALL= is the loan endpoint in this deliberately small calculus. Its
provenance check requires the source resource to remain live at the call, so a
forged =borrow; drop; call= program is rejected. A temporary argument receives
a fresh owner, is lent to the call, and is reclaimed immediately afterwards.
An existing caller-owned binder is dropped after the call only at its final
quantitative use.

Two ownership-forging cases fail closed. A borrowed producer cannot be bound
as though it allocated a fresh owner, and it cannot satisfy a consuming call
by inserting =alloc/move=. This matters for recursive transfer: proving that a
callee consumes its argument does not upgrade the caller's borrowed entry
capability into ownership.

=tests/test_qtt_anf_call.py= independently checks valid borrowed calls, rejects
owner death before the call, checks borrowed entry use and illegal movement,
and exercises production named-call lowering through the required
=borrow/call/drop= ordering. The signature and module suites now treat safe
borrowed function bodies and retaining recursive alternatives as verified;
the ordinary source recursion regression remains conservative where a
consuming edge is fed only a borrowed capability.

This is a verified lexical, call-scoped shared loan, not a general borrow
checker. There are no overlapping exclusive loans, reborrows, lifetime
variables, region outlives constraints, lexical borrowed aliases, escaping
references, or effect-sensitive invalidation yet. Those require capabilities
and loan regions to be first-class in the authoritative judgment rather than
inferred merely from instruction adjacency.

* Cycle 70: first-class loan identities in ownership ANF

The adjacency convention from Cycle 69 has been replaced by an explicit loan
context. Ownership ANF instructions now carry stable loan identities =ℓ= and a
loan kind =shared | exclusive=:

#+begin_example
borrow      %v ← &κ  loan=ℓ kind=shared
call        %r ← f(%v)       ; provenance requires ℓ ∈ Λ
end-borrow  ℓ                ; Λ,ℓ ⇒ Λ
drop        κ
#+end_example

Verification therefore operates over =Γ ; Λ= rather than reconstructing a
loan from instruction adjacency. Starting a shared loan is compatible with
other shared loans of the same root. Starting an exclusive loan conflicts with
every existing loan of that root, and a shared loan conflicts with an active
exclusive loan. Loan IDs are globally unique within the function.

Move, drop, replacement, projected move, and mutable-place write reject an
owner with an active loan. Calls check that a borrowed operand's SSA provenance,
source resource, loan identity, and active =Λ= entry agree. =end-borrow= must
name one live loan exactly once. Borrowed SSA aliases retain the loan identity,
so using or returning one after =end-borrow= is rejected.

Loan contexts are part of block state. A control-flow join is valid only when
all predecessors carry extensionally equal sets of =(ℓ, κ, kind)= entries.
This is the same branch discipline already used by the older Resource IR loan
kernel, now represented at the ownership-ANF proof boundary consumed by the
compiler pipeline.

Named-call lowering allocates deterministic loan IDs, records them on call
operands, and emits explicit =end-borrow= instructions in reverse acquisition
order before any caller-owned argument is reclaimed. The detailed proof tree
prints =ℓ#, shared/exclusive kind, and the =Λ= transition.

The sanitizer regression covers compatible shared loans, shared/exclusive
conflicts, duplicate and missing endpoints, destruction under an active loan,
dangling SSA use, mismatched branch loan contexts, call provenance, temporary
owners, and lexical owners. All 73 QTT tests pass.

This remains root-indexed ownership ANF. The older Resource IR has the stronger
projection-overlap relation; the next unification step is to put =QttPlace= on
ANF loans, then connect exclusive-loan authority to =WRITE_PLACE= and the
inferred effect row. Region variables, reborrowing, and escaping loans remain
future judgments rather than current claims.

* Cycle 71: place-indexed ANF loans and exclusive write authority

Ownership ANF loans now store the canonical =QttPlace= rather than only its
root. Their compatibility relation is exactly =qtt_place_overlaps=: roots
overlap all descendants, a prefix overlaps its subtree, certified siblings are
disjoint, and legacy opaque projections remain conservative.

The active context is therefore

#+begin_example
Λ = { ℓ ↦ (κ.p, shared | exclusive) }
#+end_example

Two exclusive loans to disjoint sibling fields may coexist. An exclusive loan
conflicts with every overlapping shared or exclusive loan; a shared loan only
conflicts with an overlapping exclusive loan. Whole-owner move, drop, and
replacement overlap every field. Projected moves conflict only with loans that
overlap the moved place. Reads of an evacuated place fail, while certified
disjoint siblings remain available.

=WRITE_PLACE= now carries an optional authority loan. A write into an
owned-heap place is valid exactly when the cited loan is live, exclusive, and
names the identical canonical place. Immediate and inline SSA mutation retains
the old authority-free rule because it does not mutate an owned heap resource.
Root ownership replacement also remains separate: =REPLACE= consumes and
destroys the displaced owned payload rather than writing through a loan.

Typed-Core projected heap writes now lower to

#+begin_example
borrow      %authority ← &κ.p  loan=ℓ kind=exclusive
write-place κ.p ← %value      authority=ℓ
end-borrow  ℓ
#+end_example

This makes mutation authority explicit at the same ownership-ANF boundary that
already carries Semantic IR's canonical =Write(place)= evidence. It does not
yet merge the effect row and loan into one proof object, but the two judgments
now cite the same exact place and the ANF verifier independently checks the
exclusive capability.

The sanitizer tests cover sibling exclusive loans, overlapping conflicts,
legacy reads during exclusivity, wrong-field authority, and successful
projected-write lowering. All 73 QTT tests pass.

Remaining gaps are reborrowing and lifetime variance, dynamic-index overlap,
loan-carrying function types, and a direct correspondence theorem connecting
each inferred =Write(p)= effect to the precise exclusive loan authorizing the
physical mutation.

* Cycle 72: effect--exclusive-loan correspondence

Projected heap mutation now has one checked account across all three semantic
levels. For every accepted Typed-Core write to =κ.p=:

#+begin_example
Semantic IR       Resource proof                 Ownership ANF
Write(κ.p)    ⇔   alias-exclusive(ℓ, κ.p)    ⇔   borrow-exclusive(ℓ, κ.p)
                  write-alias(ℓ, κ.p)             write-place(κ.p, authority=ℓ)
                  end-alias(ℓ)                    end-borrow(ℓ)
#+end_example

The correspondence checker requires the Semantic node to contain exactly the
canonical =write:<module>:<binder>:<projection>= effect. It then requires the
physical =WRITE_PLACE= to cite a nonzero loan identity, and proves that the
same block contains a preceding live exclusive borrow and a following exact
endpoint for the identical =QttPlace=. Changing only the authority identity
therefore invalidates the effect correspondence, even if the remaining ANF is
otherwise structurally plausible.

Resource elaboration and replay now generate and verify the matching
=alias-exclusive / write-alias / end-alias= certificate for projected writes.
Synthetic alias identities are deterministic and remain unique across branch
builders. The older alloc/move/drop correspondence deliberately ignores these
loan-administration transitions: they are no longer compared by a fragile
ordinal, but by the dedicated place-and-authority judgment above.

This closes the previous gap between inferred mutation effects and physical
exclusive authority for the straight-line projected-write fragment. It is not
yet a general region theorem. The authority search is block-local; loans do
not cross control-flow edges, escape in values, reborrow, or carry inferred
lifetime variables. Dynamic-index disjointness, exceptional exits, and effect
handlers also remain outside the certified fragment. The complete QTT suite
passes 73 tests.

* Cycle 73: CFG loan regions and borrowed-value provenance

Loan regions now cross basic-block boundaries without losing the evidence
attached to borrowed SSA values. A block parameter carries an optional loan
identity as part of its typing contract:

#+begin_example
Γ ; Λ ⊢ jump b(%v[ℓ])
b(%x[ℓ]) : Γ ; Λ ⊢ ...
#+end_example

For every edge argument, the verifier requires the source value's inferred
loan provenance to equal the destination parameter's declared provenance.
When that identity is nonzero it must also be present in the incoming active
loan context =Λ=. Consequently an edge cannot erase a borrowed value into an
ordinary parameter, invent a different loan, or carry the value after its
endpoint. The destination reconstructs the provenance on its local SSA name,
so ordinary operand and return checks continue to reject use-after-end.

The effect--authority correspondence is now CFG-aware. Its exclusive borrow
may dominate the write in an earlier block, and the matching endpoint may
postdominate it in a later block. The correspondence checker establishes graph
reachability, exact loan identity, kind, and place; the authoritative ANF
verifier supplies the stronger path condition by propagating =Λ= through every
edge, requiring equal incoming states at joins, and rejecting every return
with an outstanding loan. Thus the accepted theorem is the conjunction of
correspondence and verified CFG state, rather than an unsound existential
search for similarly named instructions.

Regressions exercise a borrowed value transferred through a block parameter,
erased and forged parameter provenance, use after an endpoint, and an exclusive
projected-write region split across three blocks. The focused call test is
sanitizer-backed, and the complete QTT suite passes all 73 tests.

This is the beginning of function-wide loan regions, not yet lifetime
inference. Production lowering currently creates short regions and does not
choose endpoints by liveness. There are no symbolic region variables,
outlives constraints, reborrows, escaping loan-carrying function results, or
exceptional edges. A future standalone certificate should also encode
dominance and all-path postdominance directly instead of obtaining those
properties from the conjunction with =qtt_anf_verify=.

* Cycle 74: inferred loan regions from SSA flow and postdominance

The compiler no longer requires every cross-block loan annotation and endpoint
to be manufactured by the local lowering routine. Ownership ANF now has a
region-inference pass with two coupled fixed points.

First, borrowed-value provenance is propagated over CFG edge equations:

#+begin_example
prov_b(%x_i) = prov_p(%argument_i)
prov(borrow[ℓ]) = ℓ
prov(alias %x)  = prov(%x)
#+end_example

Each destination φ-parameter begins unknown unless it already carries checked
evidence. Incoming edges unify their provenance; disagreement is rejected, not
widened away. Blocks are evaluated only after their incoming provenance is
known, which makes loop backedges constraints on the fixed point instead of an
accidental source of zero provenance.

Second, a missing endpoint is placed from borrowed SSA liveness and CFG
postdominance. The pass collects every value use, call operand, and authorized
write belonging to loan =ℓ=. It computes the standard greatest fixed point

#+begin_example
PostDom(exit) = {exit}
PostDom(b)    = {b} ∪ ⋂ PostDom(s),  s ∈ succ(b)
#+end_example

and chooses the nearest common postdominator of all uses. Within that block,
=end-borrow ℓ= is inserted immediately after the final local use. If no unique
all-path placement reaches a normal exit, inference fails closed. The ordinary
ANF verifier then independently replays the transformed program, checking
loan compatibility, edge provenance, join equality, owner liveness, exact
endpoints, and leak freedom.

The sanitizer regression covers a linear cross-block region and a diamond in
which both arms use the borrowed value. In the diamond, inference annotates
both arm parameters and places the endpoint at the join before the owner is
dropped. Erased and forged pre-existing evidence remains rejected.

Region inference is invoked by the normal compiler shadow pipeline and by the
Semantic-IR-to-ANF bridge before correspondence verification. This makes the
inferred program the artifact actually checked during ordinary compilation.

The current analysis models normal =jump/branch/return= CFGs. It does not yet
model exceptional or nonlocal exits, escaping borrowed returns, higher-ranked
regions, or reborrowing. Endpoint insertion is verified after mutation but is
not transactional on allocation failure. The postdominator matrix is also a
compiler algorithm, not yet a serialized portable proof certificate.

* Cycle 75: constrained place-narrowing reborrows

Ownership ANF now represents a reborrow as a child loan with an explicit parent
identity:

#+begin_example
Λ(ℓp) = (κ.p, exclusive, active)
κ.p ⊒ κ.p.q
────────────────────────────────────────────── reborrow-exclusive
Λ ⊢ borrow ℓc parent=ℓp at κ.p.q
    ⇒ Λ[ℓp ↦ suspended, ℓc ↦ active]
#+end_example

The containment premise uses canonical =QttPlace= prefix evidence. A root may
be narrowed to any certified descendant; a projected parent may only be
preserved or extended along the same path. Legacy opaque projections prove
containment only by equality, so they cannot accidentally manufacture a wider
capability.

An exclusive child requires an exclusive parent. Reborrowing an exclusive
parent, even as shared, suspends the parent's authority until the child ends.
During suspension, values carrying the parent loan cannot be read, passed to a
call, used to authorize mutation, reborrowed again, or ended. Ending the child
restores the parent exactly once. Ending a parent with any live child is
rejected. Nested children are represented by the same parent relation, and the
entire parent/suspension state participates in CFG join equality.

A shared parent may produce a shared child without suspension: both express
read-only authority, while the ordinary overlap rules continue to exclude any
overlapping exclusive loan. A shared parent can never produce an exclusive
child.

The sanitizer regression covers exclusive narrowing and mutation, suspended
parent use, premature parent termination, sibling widening, illegal
shared-to-exclusive escalation, parent restoration, and valid shared-to-shared
reborrowing. Parent identities are copied into compiler proof snapshots and
printed in the detailed ANF tree.

This cycle establishes a first-class checked reborrow calculus in ownership
ANF; it does not yet synthesize reborrows from source programs. Resource IR has
scoped aliases but does not yet encode the same parent relation, so semantic
correspondence for reborrows is still a unification task. Region inference also
requires explicit nested endpoints for now: dependency-ordered inference of
child endpoints before parent endpoints is not yet implemented. Escaping and
higher-ranked reborrows remain outside the claim.

* Cycle 76: unified reborrow state and dependency-ordered endpoints

Resource IR aliases now carry the same parent relation as ownership ANF. The
two verifiers enforce the same transition system:

#+begin_example
open child:  parent active ∧ parent.place ⊒ child.place
             ∧ child.kind ≤ parent.kind
exclusive parent: active → suspended
close child: child removed; suspended parent → active
close parent: permitted only when children(parent) = ∅
#+end_example

Here the authority order is =shared ≤ exclusive= only in the sense of what a
parent may safely delegate: shared may produce shared, while exclusive may
produce shared or exclusive. It is not a general subtyping claim. Canonical
place containment supplies the spatial narrowing proof in both IRs.

Resource branch equality now includes parent identity, suspension state, and
whether a child is responsible for restoring its parent. Resource reads,
moves, writes, parent termination, and further reborrows all reject suspended
authority. Shared-to-shared children remain non-suspending and compatible with
ordinary shared access.

Region inference now treats the loan-parent relation as a dependency DAG.
A parent with an unended child is deferred. Leaf children receive their
liveness/postdominance endpoint first; subsequent passes treat child creation
and child termination as uses of the parent, ensuring that the parent's
endpoint is placed after restoration rather than merely after the reborrow
instruction.

The resulting order for an entirely endpoint-free nested fragment is:

#+begin_example
borrow-exclusive ℓp
reborrow-exclusive ℓc parent=ℓp
use ℓc
end-borrow ℓc
end-borrow ℓp
drop owner
#+end_example

The Resource regression checks exclusive narrowing, child-authorized writes,
suspended parent access, premature parent closure, sibling widening,
shared-to-exclusive escalation, and shared-to-shared delegation. The ANF
sanitizer regression removes both endpoints and proves that inference restores
the child-before-parent order before ownership verification.

The semantic laws are now unified between Resource IR and ownership ANF, but
source Core still has no explicit borrowed-reference expression from which to
synthesize a reborrow. Consequently the Semantic-IR correspondence theorem
does not yet pair Resource and ANF parent edges node-for-node. Cyclic parent
graphs fail closed through lack of endpoint progress, but there is not yet a
dedicated portable acyclicity certificate or named lifetime-variable layer.

* Cycle 77: typed-Core lexical loans and authority-directed mutation

Typed Core now has an explicit scoped borrow constructor carrying a stable
loan binder, an optional lexical parent binder, an exact canonical place, and
shared or exclusive polarity. Core validation distinguishes ordinary binders
from loan binders, so a reborrow parent must name an enclosing loan rather than
merely an in-scope term variable.

Resource elaboration preserves the constructor as an exact scoped alias or
reborrow. Its environment records active loan places and polarities. Mutation
selects the nearest covering loan and requires it to be exclusive; it no
longer synthesizes a competing root loan while a parent is suspended. The
ordinary Resource verifier independently checks narrowing, parent suspension,
write authority, child-before-parent closure, and leak freedom.

Semantic IR nodes preserve and verify the loan binder, parent binder,
canonical place, and polarity. Acquiring authority remains effect-pure: the
observable effect belongs to the authorized access, not the proof-only loan.

The focused regression requires the exact
=parent → child → write → end-child → end-parent= Resource order and exact
Semantic evidence for an exclusive projected reborrow.

This closes the source-Core-to-Resource/Semantic half of the synthesis gap.
Ownership ANF does not yet lower =QTT_CORE_BORROW= into identified loan
instructions, so Semantic-ANF parent-edge correspondence and surface syntax
are not claimed. That is the next authoritative integration step.

* Cycle 78: Core-to-ANF loan synthesis and correspondence

Ownership ANF lowering now consumes typed-Core loan regions directly. Each
explicit Core loan receives a fresh operational loan ID and a stable semantic
preorder identity. A child Core parent binder resolves to the exact enclosing
ANF loan ID; the lowerer emits the borrow or reborrow, lowers the scoped body,
then emits the matching endpoint before authority returns to the parent.

The ANF lowering environment carries active loan binder, canonical place,
polarity, and operational identity. A write selects its nearest covering loan,
requires exclusive polarity, and records that loan ID on the mutation. Nested
borrow acquisition and writes contribute independently to exact demand, so the
owner is released only after the outermost endpoint.

Semantic-ANF correspondence now treats the explicit loan tree as an
authoritative proof boundary. For every Semantic loan node it requires exactly
one identified ANF borrow with the same preorder ordinal, place, polarity, and
resolved parent edge. Missing identities, duplicate ordinals, erased parents,
reparenting, widening, and polarity changes fail with a dedicated loan
mismatch before effect or generic ownership diagnostics obscure the cause.
The ordinary ANF verifier still independently checks dynamic loan state,
suspension, mutation authority, endpoint order, and resource freedom.

The sanitizer-backed regression verifies the whole path:

#+begin_example
typed Core → demand proof → Semantic IR → Resource IR → ownership ANF
           → Semantic/ANF correspondence → ANF replay
#+end_example

It also checks the three exact owner demands (outer acquisition, child
acquisition, authorized write) and counterexamples for forged Core parents,
shared mutation, erased semantic identities, erased ANF parents, widening,
and polarity forgery.

The remaining integration boundary is surface elaboration. Typed Core can now
carry and compile explicit loans end-to-end, but ordinary source syntax does
not yet introduce general borrowed references or infer nested reborrows from
place liveness. Escaping references, named lifetime variables, higher-ranked
loans, exceptional exits, and portable loan-tree certificates remain outside
the certified claim.

* Cycle 79: surface-generated projected mutation loans

Ordinary source elaboration now turns a type-certified projected mutation such
as =set! value.x replacement= into an explicit exclusive typed-Core loan around
the write. The elaborator resolves the dotted field through the layout type,
constructs its canonical projection path, allocates a module-qualified
synthetic loan binder, and scopes the mutation beneath that binder. Whole-root
=set!= remains a replacement operation because destroying and installing an
owned payload is semantically different from mutating a subplace.

The source rule is:

#+begin_example
Γ(value) = Own A      A.x = B      Γ ⊢ replacement : B
──────────────────────────────────────────────────────────── set-field
Γ ⊢ set! value.x replacement
  ↦ borrow-exclusive ℓ at value.x in write[ℓ] value.x replacement
#+end_example

Core =let/with= nodes now inherit the body type when legacy inference leaves
the source wrapper unannotated. This follows the ordinary let result rule and
prevents a fully typed projected body from losing its canonical result type at
the signature boundary.

The public compiler regression invokes =monad --trace=qtt-proof= on a normal
source module, requires a VERIFIED definition, executes the emitted binary,
and checks the visible proof sequence:

#+begin_example

borrow-exclusive ℓ at κ.1 parent=root
write κ.1 authority=ℓ
end-borrow ℓ
move κ.1
drop κ
#+end_example

The binary returns the mutated value =99=. The detailed printer now names loan
polarity in the operation itself and always prints =parent=root= or the exact
parent loan, making root acquisition and reborrowing visually distinct.

This is genuine surface-to-ANF certification in the compiler's normal shadow
pipeline. It is not yet authority over LLVM emission: the existing backend
still emits projected mutation through its legacy codegen path, and the
production cleanup planner reports its conservative fallback for this shape.
Making certified ownership ANF select or drive backend cleanup is therefore
the next production boundary. Multi-field inferred reborrow coalescing,
escaping references, higher-ranked lifetimes, and exceptional exits also
remain outside the claim.

* Cycle 80: ownership-ANF-backed production cleanup authority

The production cleanup certificate now records whether every emitted cleanup
is backed by a valid ownership ANF allocation/drop pair in addition to the
existing Semantic/Resource/destructor proof. Codegen consumes this bit from
the certificate it already uses to emit =free= and reports the selected level:

#+begin_example
[qtt] backend authority: certified ownership cleanup bindings=1
#+end_example

For the projected-mutation program, the backend agreement is:

#+begin_example
Resource:  alloc κ ; alias-exclusive ℓ κ.1 ; write[ℓ] ; end ℓ
           ; move κ.1 ; drop κ
ANF:       alloc κ ; borrow-exclusive ℓ κ.1 ; write[ℓ] ; end ℓ
           ; move κ.1 ; drop κ
Backend:   materialize layout κ ; preserve evacuated κ.1 ; free κ

The backend accepts ownership authority only when ANF independently verifies,
the same BinderId has exactly the owned allocation representation, and the ANF
program contains its final drop. The destructor descriptor and evacuation mask
still come from verified Semantic IR, so physical field destruction remains
type- and projection-directed.

This is a refinement of authority rather than a flag-day replacement. Some
previously supported interprocedural String and alias cleanup fragments still
have valid Semantic/Resource certificates while current ANF lowering cannot
represent or match their cleanup. Those plans remain safely certified at the
semantic level and are explicitly reported as =certified semantic cleanup=;
ANF availability alone never grants the stronger marker unless every cleanup
item agrees. The 23 production-memory regressions ensure this refinement does
not remove established frees.

Inapplicable analyses are no longer reported as failures. Layout literals do
not trigger the cross-scope lifetime certifier, and projected non-String writes
do not trigger the owned-String replacement certifier. A detailed proof now
shows the authority actually selected instead of unrelated fallback noise.

The public regression compiles and runs the normal source program, requires
the ownership authority marker, visible reclamation, no cleanup fallback, and
result =99=. The remaining unification gap is extending ownership ANF over all
currently semantic-only call/alias cleanup fragments, then requiring the
strong marker universally. Direct instruction selection from ownership ANF,
rather than certified plan selection inside legacy codegen, is later work.

* Cycle 81: environment-aware expression ANF at backend call boundaries

Backend cleanup fragments now lower typed-Core expressions with the same

=qtt_anf_lower_core_in_env= is the expression-level entry point: it derives and
validates demand evidence, preserves the signature environment on the ANF
program, and resolves named calls through canonical parameter, result,

This closes a real authority gap. A dead fresh result such as

#+begin_src scheme
(with [text (fresh-prefix "abcdef")]
  7)
#+end_src

now has one independently checked chain:

#+begin_example
SignatureEnv(fresh-prefix) → Core named apply → ANF call(owned/fresh)

The normal compiler reports =certified ownership cleanup= for this
interprocedural case. Its LLVM regression requires call-before-destructor

Ownership ANF is not yet universally authoritative. Literal-owner plus

* Cycle 82: structured effects and quantitatively graded resumptions

The effect-row kernel now has a semantic atom distinct from its presentation.
An occurrence records its constructor and kind, canonical payload type,
generative capability identity, operation, scopedness, and an exact
=N union {omega}= resumption quantity. Consequently two =State= handlers with
the same payload and operation but different capabilities cannot unify or be
handled accidentally, and changing a continuation from linear to multi-shot
changes both equality and its stable fingerprint.

Rows preserve Koka-style duplicates and principal open-tail unification. A
handler removes one exact structural occurrence, not whichever printed label
happens to compare equal. Canonical ordering and fingerprints are deterministic
and do not depend on pointer identity or host structure padding. The legacy
string API remains available for existing compiler producers while they are
migrated rule by rule.

This establishes the intended synthesis:

#+begin_example
surface:       inferred row epsilon, normally hidden when empty
typed atom:    State[type=A, capability=h, operation=get, resume=1]
elaborated IR: explicit capability/evidence h
ownership:     continuation capture checked at quantity 1
#+end_example

The sanitizer regression covers distinct generative capabilities, exact versus
unrestricted resumptions, fingerprints, formatting, one-instance handling,
and structural open-row unification. This is still a kernel milestone:
authoritative HM arrows do not yet carry =epsilon=, ordinary inference does not
yet generate these atoms, and handlers/evidence passing are not implemented.
The next vertical slice is effect-bearing arrow contracts plus inference for
pure terms, application, mutation, allocation, FFI, and known primitives.

* Cycle 83: effect semilattice and checked compositional judgments

Closed effect rows now have an explicit least-upper-bound operation. Effects
describe required capabilities rather than dynamic operation counts, so the
join uses maximum multiplicity. It satisfies the executable laws

#+begin_example
epsilon join epsilon = epsilon
epsilon1 join epsilon2 = epsilon2 join epsilon1
(epsilon1 join epsilon2) join epsilon3
  = epsilon1 join (epsilon2 join epsilon3)
#+end_example

while preserving duplicate occurrences that name genuinely distinct or
polymorphically masked handler instances. The operation rejects unresolved
open tails: those require row constraints and unification rather than an
unsound closed approximation.

Semantic IR consumes this algebra. Strict Core constructs join the effects of
the expressions they evaluate; place reads and writes contribute intrinsic
effects; lambda construction is pure; and applying a syntactic lambda adds its
latent body effect. For example, a write beneath a sequence is present in the
sequence's summary, while the lambda value enclosing that write remains pure
until invoked.

The verifier does not trust the stored summary. It recursively interprets the
typed-Core term using the declarative rules and compares the resulting closed
row with the IR certificate. The sanitizer regressions cover the semilattice
laws, open-row rejection, strict sequencing, pure lambda construction, latent
direct application, and effect-certificate verification.

This is a real metatheoretic boundary, but not yet a full effect-soundness
theorem. Named and indirect calls need latent rows in canonical signatures;
HM arrows and schemes still do not carry effect variables; exception/control
edges and handler resumptions are not yet represented. The next cycle should
put these checked rows into function signatures and make named application
consume them before changing surface syntax.

* Cycle 84: latent effects become callable contracts

Canonical function signatures now own a closed latent effect row, its solver
arena, an explicit completeness bit, and a stable row fingerprint.  The effect
fingerprint participates in the callable contract fingerprint, so changing a
function's latent capability requirements invalidates cached call evidence in
the same way as changing a parameter grade or result ownership contract.

Signature validation is not a self-check over stored metadata.  It interprets
typed Core again in a fresh effect arena, compares the canonical structural
presentation and fingerprint, and rejects a substituted or stale row.  Closed
rows can be cloned safely across arenas; external module declarations deep-copy
this owned evidence instead of retaining aliases into another signature's
lifetime.

Named Semantic-IR application now resolves a complete callee contract and
joins its latent row with evaluation effects from the callee expression and
arguments.  Its independent verifier performs the same lookup and derivation,
so a named state write is observable at the caller root even though the write
is not syntactically present there.  Legacy hand-built contracts without an
effect proof remain explicitly incomplete and contribute no claimed latent
row; they are not silently relabelled as certified pure contracts.

This cycle does not yet establish interprocedural effect soundness for all
programs.  A signature containing unresolved named calls is marked incomplete;
recursive call graphs need a monotone SCC fixed point, imported interfaces must
serialize structural atoms and schemes, indirect calls need effect-bearing
arrow types, and handlers still need typed capability/evidence elaboration.
Those are the next proof obligations.  The focused signature, environment,
module, named-call, ANF, and Semantic-IR regressions pass, as does the complete
QTT test discovery; the compiler build also succeeds.

* Cycle 85: recursive least effects and subsystem extraction

Module effect inference now solves the mutually recursive equation system

#+begin_example
epsilon_f = intrinsic(f) join join { epsilon_g | f calls g }
#+end_example

by ascending Kleene iteration over the finite closed-row semilattice.  A
syntactic body supplies the bottom-relative intrinsic seed; named callees add
their current canonical rows; iteration stops only when every signature row,
fingerprint, and completeness proposition is unchanged.  The resulting
=QttEffectFixedPoint= records convergence, iterations, changes, and the number
of incomplete definitions.

Convergence and completeness are intentionally distinct.  A closed recursive
SCC can converge to a complete least solution.  A call to a missing or
uncertified external function also converges, but its contract remains
incomplete and cannot be advertised as pure.  Fixed-point tests cover
mutually-recursive propagation, declaration-order independence, stable
fingerprints, and unresolved-call propagation.

Environment-aware signature validation now re-derives latent rows with the
same callable environment used during inference.  ANF therefore checks the
enriched contract rather than comparing it with a context-free approximation.
An explicit =effects_environment_solved= proof-state bit distinguishes a
context-free provisional signature from one closed against =Sigma=; it is
fingerprinted with the contract and prevents accidental use of the stronger
validator before fixed-point inference has occurred.
Module verification runs effect solving before Semantic IR and ownership
transfer solving, making the inferred rows available to ordinary lowering.

The algebra implementation has moved from =qtt/= to the peer =effects/=
subsystem.  QTT retains only a compatibility include and the integration rules
that connect effects to grades, ownership, calls, and IR.  Make, CMake, and all
standalone test harness manifests compile the implementation from its new
home.  =effects/README.org= defines the ownership boundary and planned
decomposition.

This is not yet the final recursive theorem.  The present domain is finite
closed rows, the iteration is module-wide rather than SCC-scheduled, and the
termination bound is defensive executable evidence rather than a mechanized
height proof.  Open effect variables, polymorphic recursion, indirect calls,
serialized schemes, and handler-generated atoms remain outside this result.

* Cycle 86: HM effect schemes and known indirect application

HM =TypeScheme= now carries an effect scheme and an explicit completeness
proposition beside its quantitative grade scheme.  Scheme cloning retains both
pieces of evidence, destruction releases them exactly once, and effect schemes
have reference-counted ownership independent of their backing row arena.

Quantitative instantiation now produces one coherent callable instance:

#+begin_example
instantiate (forall alpha epsilon. A -{epsilon}-> B)
  = (A[alpha := beta] -{epsilon := eta}-> B[alpha := beta], rho, eta)
#+end_example

Type variables, domain grades, closure grades, and effect-row variables are
freshened together inside one inference context.  In particular, repeated
instantiation of an open effect scheme produces distinct row variables in the
same solver namespace; numeric identities from unrelated arenas are no longer
mistaken for generativity.  The instance exposes its latent row, solver, and
completeness proof, and its normal destructor preserves the context-owned
solver lifetime.

Effect-scheme fingerprints are alpha-invariant: quantified tail names are
normalized to one binder marker while structural atoms remain significant.
Thus cloned schemes have the same identity, repeated instances have fresh
variables, and a pure arrow differs from an otherwise identical =io=-bearing
arrow.

Semantic IR also propagates latent effects through statically proven lexical
callable aliases.  Its emitter and independent verifier reconstruct the same
callable environment through =let= bindings; invoking an effectful lambda via
a variable therefore exposes its write at the enclosing expression root.
Unknown indirect calls continue to fail closed.

This is the first real effect-bearing HM representation, not yet full effect
inference.  Ordinary source generalization does not yet derive effect
constraints into =TypeScheme=, partial application needs per-arrow latent
effect placement, arbitrary closure/data flow lacks callable evidence, and
module interfaces do not serialize schemes.  Those are the next authoritative
integration steps.

* Cycle 87: ordinary source effect derivation

Effect schemes are now produced during the normal HM definition path, not only
by QTT test harnesses or post-typed-Core signatures.  After a lambda is typed
and generalized, source effect interpretation derives its latent body row and
attaches the generalized scheme and completeness witness to the same
=TypeScheme= that owns its type and grade evidence.

The source rules currently certify:

#+begin_example
Gamma |- literal : A ! {}
Gamma |- lambda x. e : A -> B ! {}       (effect(e) is latent)
Gamma |- set! x v : A ! {state.write} join effect(v)
Gamma |- heap-array es : Array A ! {alloc} join effects(es)
Gamma |- asm ... : A ! {ffi}
Gamma |- f xs : B ! effects(xs) join latent(instantiate(f))
#+end_example

Strict arrays, sets, maps, sequences, special forms, and application arguments
compose through the closed-row join semilattice.  A call imports its callee row
only when the HM environment provides a complete effect scheme.  Missing or
uncertified functions propagate incompleteness instead of becoming pure by
default.

Lambda construction and execution are separated explicitly.  A nested lambda
is pure as a value even when its body writes state; the body row becomes the
function's latent scheme.  This matches the typed-Core/Semantic-IR rule and
removes another disagreement between the source and lower-level judgments.

Legacy schemes with only a saturated row remain conservative under partial
application.  Cycle 88 replaces that compatibility limitation for ordinary
definitions with arity-checked per-arrow contracts.

The sanitizer regression constructs ordinary AST lambdas and checks mutation
plus certified IO composition, unknown-call incompleteness, nested-lambda
latency, partial versus saturated currying, heap allocation, and foreign/ASM
effects.  The existing HM scheme and complete QTT suites remain green.

The next theoretical step is an open-row constraint judgment integrated with
HM unification.  It must assign a latent row to every arrow stage, solve
application inclusion/equality constraints, generalize row variables under the
value restriction, and instantiate residual schemes after partial application.
Primitive and FFI effects should then come from explicit trusted manifests,
not name heuristics.

* Cycle 88: curried arrows own staged effect contracts

=TypeScheme= now owns a vector of latent effect schemes aligned one-for-one
with the leading arrows of its HM type.  Quantitative instantiation rejects an
effect/type arity mismatch just as it already rejected a grade/type mismatch,
freshens every stage into the call site's shared effect arena, and exposes an
atomic domain contract operation:

#+begin_example
take : (A -> B, rho, epsilon, complete) -> (B, A, rho, epsilon, complete)
#+end_example

The operation advances type, grade, and effect offsets together.  A caller
cannot consume a parameter while accidentally retaining the previous arrow's
effect evidence.  Scheme cloning retains every stage; destruction releases
them; and the callable fingerprint includes ordered stage schemes and their
completeness witnesses.

Ordinary source definitions synthesize pure contracts for closure-building
stages and place the inferred body effect on the final stage.  Consequently,
for =f : A -> B -> C= with stages =[{}, {io}]=, evaluating =f a= is certified
complete and pure (apart from evaluating =a=), while =f a b= imports ={io}=.
The saturated =effect_scheme= remains as a checked compatibility projection
for existing consumers; old schemes lacking a vector still fail closed on
partial application.

Sanitizer tests cover pure partial/effectful saturated application, stage
freshening, atomic evidence consumption, clone/fingerprint stability, and
malformed stage arity.  Focused HM/indirect-call tests and the full compiler
build are green.

This is not yet principal open-row inference.  A row-polymorphic stage can be
instantiated, but source composition still joins only closed rows and marks an
open join incomplete.  Nor does an arbitrary residual closure stored in data
yet carry its remaining vector through general higher-order flow.  The next
cycle should make row constraints authoritative during HM inference, then
serialize the staged scheme in module interfaces.

* Cycle 89: open rows preserve known effects

Source composition previously had a lossy fallback: if either operand was
open, it marked the result incomplete and returned the left row unchanged.
Thus composing ={state.write}= with =<network | e>= could forget =network=
entirely.  Incompleteness prevented an unsound purity certificate, but the
summary itself was needlessly weak and diagnostics could hide known effects.

The effect kernel now provides a general join with the abstract rule

#+begin_example
known(<L | e>)       = L
known(r join s)      = known(r) join_max known(s)
tail(r join s)       = {}                         when r,s are closed
                     = fresh existential remainder otherwise
#+end_example

Here =join_max= is the existing multiset maximum, so known-effect composition
remains commutative, associative, and idempotent modulo the identity chosen for
the abstract remainder.  The fresh tail denotes effects not represented by
the known lower-bound component.  Source inference retains =complete = false=
whenever this abstraction is required; the tail is therefore not mistaken for
a solved principal constraint.

=qtt_effect_join_closed= remains a checked compatibility theorem boundary: it
rejects an open operand and delegates to the general operation only after both
closure obligations hold.  Ordinary source inference uses the general join,
so mutation plus one or several fresh instantiations of an open network effect
retains both =state.write= and =network=, with network multiplicity joined
idempotently and the incompleteness witness preserved.

Sanitizer regressions cover open/open composition, known-label preservation,
idempotence, closed-wrapper agreement, repeated polymorphic calls, and fresh
remainders.  This is a meaningful robustness step, but not yet the promised
principal effect inference: the solver still lacks explicit inclusion/union
constraints relating the result tail to both operand tails.  That constraint
language, its generalization discipline, and value restriction are the next
theoretical boundary.

* Cycle 90: effect constraints become a separate proof boundary

The =effects/= subsystem now owns an executable constraint language rather
than relying only on immediate row operations. It represents equality
=epsilon = delta=, inclusion =epsilon <= delta=, and join
=theta = epsilon join delta=. Closed propositions are decided exactly; open
information uses =proved/refuted/residual= instead of treating an unresolved
tail as a Boolean answer.

The batch solver produces =SOLVED= only when every obligation is proved,
=REJECTED= when any obligation is refuted, and =RESIDUAL= otherwise. Its
certificate retains the ordered obligations and their statuses. A separate
replay path recomputes their row semantics and rejects a purported acceptance
certificate containing a refuted obligation.

The sanitizer regression covers closed subrow proofs, exact closed joins,
equality, an open-tail residual, rejection, status ordering, and certificate
replay. Make discovers the new source through =effects/*.c= and CMake lists it
explicitly. The independent CMake build also exposed and repaired an older
manifest omission of =qtt/evidence.c=; both build graphs now link the same
shadow-demand verifier.

This kernel is foundational, not yet principal HM effect inference. It does
not calculate most-general tail substitutions, canonicalize residual sets,
compute free row variables of the environment, or serialize proof terms. The
new end-state roadmap in =effects/README.org= gates algebraic/scoped handlers,
graded resumptions, ownership capabilities, modal effects, effect quantales,
commutativity evidence, and coeffects behind those Phase-I requirements.

* Cycle 91: a principal inclusion fragment and fixed-point solver

Effect inclusion is now constructive when its lower row is closed and its
upper row has an open tail. For lower known multiset =L= and upper known
multiset =K=, the solver computes =missing = L \\ K= and binds
=rho := <missing | gamma>= with fresh =gamma=. Keeping the fresh remainder
makes the substitution most general: later lower bounds can extend it without
invalidating or prematurely closing the earlier solution.

Repeated lower bounds accumulate through the solver binding chain. Tests solve
IO/state and allocation bounds in both orders and obtain the same canonical
known multiset modulo fresh-tail identity. Open lower tails remain residual,
because their inclusion requires a relation the current equality-based row
solver cannot yet represent. Reflexive open inclusion is proved directly.

Closed join operands also solve a fresh or open result through exact join and
unification. Batch solving now iterates monotonically to a fixed point instead
of issuing certificates after one insertion-ordered pass. A later equality can
therefore close a tail and discharge an earlier residual inclusion; replay
checks the statuses against the final substitution.

The sanitizer regression covers most-general refinement, multiple accumulated
bounds, order independence, exact open-result join solving, open reflexivity,
fixed-point discharge, genuine open residuals, rejection, and certificate
replay. Focused effect/source/quantitative tests and the Make build remain
green.

This establishes a principal fragment, not full principality. Open-lower
inclusion, tail-to-tail inequalities, canonical residual constraint graphs,
environment-aware generalization, and portable certificates remain required
before HM source inference may treat this solver as authoritative.

* Cycle 92: persistent open inequalities and cyclic graph solving

Open-to-open inclusion now makes constructive progress without pretending that
inclusion is equality. For =<L|alpha> <= <K|beta>=, every known atom missing
from =K= is inserted into =beta='s binding with a fresh remainder. The
original inclusion remains residual, preserving the unsolved relationship
between lower and upper tails for future substitutions.

Once the known difference is empty the rule stops allocating, so fixed-point
iteration terminates. Repeated identical residual obligations are deduplicated
in certificates; proved obligations remain individually visible. The
sanitizer regression inserts the same open inequality twice, observes its
known =network= bound in an =io=-headed upper row, and obtains one replayable
residual node.

The solver builds the finite directed graph of subrow obligations and computes
transitive reachability. By antisymmetry, every strongly connected component
denotes row equality. One representative is unified with each SCC member
before normal discharge. A three-variable inclusion cycle is therefore solved
and replayed as equality without introducing a recursive row binding.

This is still not a globally canonical portable graph. Node identity is tied
to the live row arena, residual ordering preserves first source occurrence,
and acyclic tail-to-tail bounds are retained rather than transitively reduced
or generalized into HM schemes. Those are the next authority requirements.

* Cycle 93: alpha-normalized effect certificates

Constraint certificates now export deterministic proof text and a stable
fingerprint after solving. Every referenced row is formatted through the final
substitution, so refinements and SCC equalities are reflected. Raw arena tail
numbers are replaced with locally quantified names =e0=, =e1=, ... in first
structural occurrence order. Constraint kind and logical status participate in
both text and fingerprint.

The sanitizer regression constructs equivalent open residual graphs after
different amounts of unrelated fresh allocation. Their normalized text is
byte-identical, contains local =e0= rather than allocator history, and hashes
to the same nonzero identity. Existing replay still succeeds before and after
export.

This removes allocator identity from certificate comparison, but it is not yet
full portability. Certificate ordering remains stable source order; there is
no versioned grammar, parser, cryptographic digest, or reconstruction of row
objects in a fresh process. The next certificate cycle should canonicalize
graph order, define a versioned serialization grammar, parse it into an
arena-independent proof object, and replay closed claims without compiler AST
or source rows.

* Cycle 94: structure-first certificate ordering

Effect certificate text now begins with
=monad-effect-certificate-v1=. Export computes alpha-insensitive ordering keys
from fully resolved rows by replacing each concrete tail with =e*=, sorts
obligations by kind/status/shape, canonicalizes commutative join operands, and
only then assigns local =e0,e1,...= names. Stable fingerprints consume this
ordered representation.

The sanitizer regression builds two independent open residual inequalities,
then rebuilds them with different tail identities and reversed insertion
order. Their proof text and fingerprints are identical. This extends Cycle
93's allocation independence to ordinary graph-order independence.

The remaining claim is deliberately narrower than “canonical graph
serialization.” Structurally symmetric wildcard keys still fall back to source
order, the human row spelling does not escape arbitrary labels, and =v1= has
no parser or source-free checker. Exact symmetric-graph labeling plus a
length-delimited portable grammar are the next certificate milestones.

* Cycle 95: ordinary HM effects consume the constraint solver

The normal lambda effect path now opens a per-derivation constraint scope.
Every sequence, collection, argument, callee-stage, and body composition emits
an exact join obligation for the candidate result row. At the lambda boundary,
the solver reaches its fixed point and an independent replay checks the
certificate before generalization.

Rejected, exhausted, or unverifiable evidence fails scheme production.
Residual evidence preserves the inferred conservative row but forces
=effects_complete = false=. Complete contracts therefore require both the
source interpreter's coverage witness and a solved/replayed constraint batch.

=InferCtx= records the last obligation count, canonical certificate
fingerprint, and residual status. The existing QTT diagnostic line reports
these fields as =effect-constraints=, =effect-certificate=, and
=effect-status=. The sanitizer source regression checks that mutation plus a
closed IO call produces nonempty solved evidence, while repeated calls through
an open network scheme produce nonempty residual evidence and revoke
completeness.

This is real compiler integration, but not yet a fully unified HM judgment.
The recursive source interpreter still constructs candidate rows before
emitting constraints, and effect variables are not generalized against free
variables of the HM environment. Those are the next semantic-unification
tasks.

* Cycle 96: generalized effect schemes own their evidence

Constraint evidence is no longer merely a transient observation on
=InferCtx=. Successful lambda generalization copies the canonical
=monad-effect-certificate-v1= text, obligation count, stable fingerprint, and
solved/residual classification into the reference-counted =QttEffectScheme=.
The evidence consequently follows the latent effect contract through scheme
retention and =TypeScheme= cloning.

The focused sanitizer regression destroys one reference to an inferred scheme
and confirms that the retained scheme still exposes the same nonzero evidence
fingerprint. Ordinary QTT diagnostics now read this owned witness, avoiding a
misreport when later or nested inference overwrites the context's last-result
fields.

This establishes an ownership boundary, not yet external proof carrying.
Certificate =v1= remains an export-only grammar: there is no parser,
source-free replay checker, manifest encoding, or interface compatibility
rule. Candidate rows are also still produced before their join constraints.
The next unification step is a bidirectional judgment that returns a row and
its obligation derivation together, followed by an independent certificate
parser/checker for module boundaries.

* Cycle 97: one source-effect judgment, explicit coverage failures

The source walker and join generator now share a single lexical
=SourceEffectJudgment=. It carries the candidate row context, exact constraint
set, append health, and accumulated coverage gaps. The former mutable
=InferCtx.active_effect_constraints= and =effect_constraint_failed= side
channel has been deleted. Every recursive composition must now return its row
through the same object that receives its proof obligation.

The previous mutable completeness boolean has also been replaced internally by
a monotone reason set. Schemes distinguish open rows, unknown callees,
incomplete imported contracts, legacy partial calls, arrow/effect arity
mismatches, and residual solver obligations. This makes the important logical
distinction explicit: “all generated constraints solved” does not imply “the
source derivation covered every effectful call.” Diagnostics expose the reason
set as =effect-coverage=.

Finally, scheme evidence attachment validates both the =v1= header and a
recomputed stable fingerprint. The sanitizer regression covers solved versus
residual evidence, unknown-call coverage despite solved equations, open-row
coverage, pure nested lambdas, rejected mismatched fingerprints, evidence
retention, and integrity checking.

This is a meaningful unification but not yet the final bidirectional HM
judgment. Type inference still precedes this effect walk, effect variables are
not generalized relative to the free variables of the typing environment, and
certificate text cannot yet be parsed and replayed in a fresh process.

* Cycle 98: compiler-facing typed effect judgments

The public inference boundary now returns an =InferExpressionJudgment= that
owns a solved HM type, effect scheme, and completeness result. It works for
both latent lambda bodies and immediately evaluated expressions. A heap array,
for example, returns its ordinary HM array type together with an =alloc=
effect contract and verified certificate.

=env_hm_infer_define= consumes this combined judgment, so normal definition
compilation no longer performs unrelated top-level type and effect calls and
then attempts to associate their results manually. The effect witness remains
alive through type generalization, stage-contract construction, diagnostics,
and environment insertion, and is released through one explicit judgment
lifetime operation.

The focused sanitizer harness exercises the public combined API for a latent
IO function and a non-lambda allocation, in addition to the coverage and
certificate cases from Cycle 97.

The claim remains deliberately precise: this is one compiler-facing judgment
value, but its two components are still generated by consecutive internal AST
walks. The next cycle must start fusing recursive HM cases with effect
production; only after that will the implementation directly realize
=Sigma ; Psi | Gamma |- e : A ! epsilon |> Delta= rather than packaging two
analyses at their boundary.

* Cycle 99: the first recursively fused typing/effect rules

Atomic literals, arrays, sets, and maps now implement one recursive judgment
that produces their HM type and effect row simultaneously. Container children
contribute both unification constraints and effect-join obligations during the
same visit. A heap array introduces =alloc= in its typing rule, and a map whose
value is such an array transports that effect through the nested derivation.

=InferExpressionJudgment.recursively_fused= makes the authority boundary
observable. The flag is true only when the entire expression belongs to the
fused fragment; mixed or unsupported syntax continues through the older but
certified fallback. This avoids quietly equating boundary packaging with a
syntax-directed implementation.

Differential regression coverage compares important behavior inherited from
the mature HM walker. In particular, radix literals remain integral even when
their digits contain =e=, while decimal/exponent spellings remain floating.

This is the beginning, not completion, of the final judgment. Calls,
sequencing, conditionals, lexical binding, mutation, and lambdas still require
fused rules. Calls are the highest-value next step because they connect effect
scheme instantiation, arrow-stage effects, type application, coverage gaps,
and higher-order behavior at one semantic point.

* Cycle 100: fused direct application and simple definitions

Direct calls whose arguments belong to the fused fragment now construct type
and effect evidence in one recursive rule. The rule instantiates the callee HM
scheme, constrains each argument against its corresponding arrow domain,
returns the residual arrow after partial application, and joins exactly the
effect schemes of the stages actually reached. Open stage rows propagate
residual obligations and coverage gaps rather than being silently closed.

The fused lambda rule creates the lexical HM environment, assigns fresh domain
types, derives each body expression, joins latent body effects, and constructs
the arrow type in the same traversal. It is authoritative for simple
unannotated lambdas whose bodies remain inside the fused fragment. Nested
lambda expressions are deliberately excluded for now so closure construction
cannot be confused with execution of the nested latent computation.

Regression coverage exercises saturated IO calls, pure partial application,
the effectful final stage of a curried call, open-row calls, simple latent IO
lambdas, nested container effects, and the earlier radix parity case. The
=recursively_fused= witness remains false for every fallback derivation.

The next semantic boundary is higher-order application: a callee obtained from
an expression or parameter needs a type-indexed effect contract rather than a
name lookup. After that, conditionals and lexical binding must merge effect
rows and coverage evidence path-sensitively.

* Cycle 101: fused sequencing, alternatives, and an honest higher-order gap

The fused fragment now includes ordinary =begin= sequencing and standard
=if= expressions. Sequencing returns the final expression's HM type while
joining all evaluation effects. Conditional inference constrains its condition
to =Bool=, unifies its branch types with the mature optional/nil promotion
rule, and joins condition/then/else rows in one certified derivation. An IO
operation in only one alternative therefore remains visible in the enclosing
effect scheme without pretending that both alternatives execute.

The higher-order fallback is also more informative. After HM inference, a
lexical callee can be known to have an arrow type even though no effect contract
survives for that value. Such calls now produce
=missing-arrow-contract= rather than the less accurate =unknown-callee= gap.
The sanitizer regression constructs exactly this function-parameter call and
requires incomplete, non-fused evidence with the new reason.

The next required representation change is consequently explicit: latent
effect schemes and their completeness/certificate identity must be attached to
arrow-typed values or substitutions. Once that exists, higher-order call
fusion can instantiate the contract from the callee expression just as direct
calls currently instantiate it from a named =TypeScheme=.

* Cycle 102: existential higher-order arrow contracts

The first-class arrow boundary now has an executable conservative model.
Every unannotated lexical parameter receives both a fresh HM type and a fresh
existential latent-effect tail. When that parameter appears in callee position,
the fused application rule constructs an arrow from the inferred argument
types to a fresh result, constrains the parameter type against it, and joins
the parameter's latent tail into the surrounding derivation.

The higher-order sanitizer regression has changed authority: it must now be
recursively fused, carry an open/residual effect scheme, and no longer report
=missing-arrow-contract=. This turns a named architectural gap into a real
typed rule while remaining conservative about arbitrary function arguments.

What is not honest yet is correlation at instantiation. The generalized open
tail records “this function performs whatever its functional argument
performs,” but the type scheme does not yet bind that tail to a particular
arrow domain. Calling the higher-order function with a known effectful argument
therefore cannot specialize the tail to that argument's contract. The next
step is a correlated type/effect substitution over arrow domains, analogous to
the correlated quantitative substitutions already used for callable grades.

* Cycle 103: callable-domain provenance survives generalization

Higher-order effect schemes now record exactly which outer lambda parameters
were invoked in callee position. The fused lambda environment retains stable
parameter-scheme identities during derivation; application marks the matching
domain; effect generalization serializes the ordered domain indices into the
reference-counted =QttEffectScheme=. These indices also contribute to the
scheme fingerprint, because two equal-looking open rows with different
callable-domain dependencies are not semantically interchangeable.

The higher-order regression requires one callable dependency at domain zero
for =lambda f v -> f v=. Ordinary lambdas retain an empty dependency set. This
is the first half of correlated substitution: generalization now preserves the
provenance needed to decide which argument effect should instantiate the open
tail.

The second half remains: application of such a generalized scheme must inspect
the corresponding function argument's effect contract and substitute it for
the quantified tail. Multiple callable domains will require a genuine effect
expression (or row-variable vector), because one flat open tail cannot encode
independent dependencies without collapsing their correlation.

* Cycle 104: the first correlated higher-order effect substitution

Named higher-order calls now consume the callable-domain provenance preserved
by Cycle 103. When an reached arrow stage depends on exactly one functional
parameter, application obtains that argument's stored effect scheme,
instantiates it in the current inference arena, and substitutes the resulting
row for the stage scheme's quantified tail. The substitution is structural and
capture-avoiding: known labels on the outer stage are retained, while the one
bound existential is replaced by the argument contract.

The sanitizer regression checks the complete three-way boundary for
=applyHigher f v = f v=: specialization with a pure function produces a closed
empty effect row; specialization with =ioFn= produces a closed row containing
exactly one =io= label; specialization with an incomplete =openNetwork=
contract preserves =network= and an open tail. The last case is as important as
the first two: specialization is not allowed to manufacture completeness.

The rule is intentionally narrow. It presently recognizes a named functional
argument and uses that symbol's saturated effect contract. It therefore does
not yet model an arbitrary expression-valued closure, multiple independently
effectful callable parameters, or the per-stage effects of a curried callable
argument. Those require effect variables attached to arrow domains and a
vector-valued substitution carried through HM instantiation. Until then these
shapes keep conservative residual evidence rather than being guessed.

* Cycle 105: saturated multi-domain correlation

Call-site substitution now consumes every callable-domain index on an effect
stage. For each index it requires a named argument with a stored effect
contract, instantiates that contract in the active arena, and combines the
contracts with the canonical effect-row join. The resulting row replaces the
stage's quantified tail. Completeness is derived by conjunction over all
argument contracts.

The regression constructs =applyBoth f g v= whose body evaluates both =f v=
and =g v=. Its generalized scheme records domain indices zero and one. Applying
it to closed =ioFn= and =networkFn= contracts produces a closed row containing
exactly one =io= and one =network=. Replacing the second argument with residual
=openNetwork= preserves both known labels and the open tail; the result remains
incomplete. This checks useful specialization and its negative soundness
boundary together.

This cycle solves saturated multi-domain union, not independent domain
polymorphism. The generalized row still owns one existential tail, so partial
application cannot retain separate substitutions for =f= and =g=. The next
representation step is an effect expression whose variables are keyed by
arrow-domain identity and whose substitution environment is instantiated with
the HM arrow scheme.

* Cycle 106: callable invocation depth becomes semantic evidence

Callable provenance is now an ordered sequence of pairs =(parameter, depth)=,
not merely a set of functional parameter indices. The fused application rule
records how many arrow domains were supplied whenever a lexical parameter is
invoked. Generalization copies those depths into the reference-counted effect
scheme, and the semantic fingerprint hashes both coordinates. Equal rows that
invoke the same parameter to different depths no longer identify as the same
contract.

At specialization, an argument with arrow-stage contracts contributes only
the stages below the recorded invocation depth. This fixes the curried
counterexample: if =curriedIo : Int -> Int -> Int= has a pure first stage and
an =io= second stage, then =applyHigher curriedIo 2= returns an arrow with a
closed empty evaluation row. Importing its saturated =io= projection at that
point was observably too strong and could inhibit valid optimization.

The integration regression first re-infers a fresh polymorphic higher-order
scheme, checks that its callable contract is =(domain 0, depth 1)=, applies it
to =curriedIo=, and requires both an arrow result and zero =io= labels. Kernel
coverage separately requires depth to affect effect-scheme fingerprints.

This is stage-sensitive saturated substitution, but it does not yet carry a
partially instantiated dependency environment on the returned arrow value.
That requires first-class effect expressions attached to arrow codomains, so
substituting one supplied functional argument preserves the remaining domain
variables for a later call.

* Cycle 107: returned arrows retain latent stage evidence

The combined HM/effect judgment now distinguishes the effects of evaluating
an expression from the effects latent in an arrow returned by that expression.
=InferExpressionJudgment= owns a reference-counted arrow-stage vector in
addition to its evaluation scheme. A partial direct call exports the unused
suffix of its callee's stage vector, and judgment destruction releases every
retained scheme.

Lambda inference composes its own application prefix with that residual
suffix. For =lambda x -> curriedIo x=, where =curriedIo='s first stage is pure
and its second stage performs =io=, the inferred type is
=Int -> Int -> Int= and the authoritative stage vector is =[pure, io]=. The
old definition reconstruction placed the lambda's pure body row at the final
arrow and therefore produced =[pure, pure]=, silently losing the latent IO.

=env_hm_infer_define= now installs the judgment-owned stage vector whenever its
length agrees with the inferred arrow type. Its historical pure-prefix/final-
body reconstruction remains only as a conservative compatibility path for
non-fused judgments that do not yet produce stage evidence.

The sanitizer regression checks both boundaries: direct partial application
has an empty evaluation row plus one returned =io= stage, and wrapping that
partial call in a lambda produces the complete two-stage =[pure, io]= contract.

This makes ordinary definitions preserve direct residual callable effects. It
does not yet solve a partially applied /higher-order substitution/ such as
=applyBoth ioFn=, because the one remaining flat existential cannot retain the
already-bound =ioFn= substitution while independently quantifying the missing
callable argument. That remains the motivation for domain-indexed effect
expressions rather than a larger flat-row encoding.

* Cycle 108: higher-order substitutions survive split application

Residual-stage construction now performs a real partial substitution instead
of copying the original callee suffix unchanged. Given a stage depending on
callable domains =D= and =k= supplied outer arguments, it partitions

#+begin_example
D_bound = {(i,a) ∈ D | i < k}
D_free  = {(i-k,a) | (i,a) ∈ D ∧ i ≥ k}.
#+end_example

Every bound dependency contributes the prefix of its actual argument's stage
contract selected by invocation depth =a=. If =D_free= is nonempty, a fresh
tail represents precisely that unresolved union; its shifted pairs become the
callable provenance of the newly generalized residual scheme. In compact form,

#+begin_example
α(D) [ supplied σ ] = (⨆_{d ∈ D_bound} σ(d)) ⊔ β(D_free).
#+end_example

The split-call regression partially applies =applyBoth= to =ioFn=. Its final
residual stage contains the known =io= label, stays open, and records only the
remaining callable as domain zero. The returned scheme is installed as
=applyBothIo=; applying that value to closed =networkFn= and the ordinary value
then produces a complete closed row containing exactly one =io= and one
=network=.

Crucially, residual openness is not added to the evaluation judgment's coverage
gaps. Evaluating the first partial call is closed and pure; uncertainty belongs
to a future arrow stage. This preserves the semantic separation introduced in
Cycle 107.

This implements sequential substitution for the current join-shaped effect
expressions. It is not yet a general effect-expression language: duplicated
dependencies with distinct control provenance, expression-valued closures,
and serialization of residual substitutions remain open work.

* Cycle 109: inline lambdas become first-class effect arguments

Higher-order correlation no longer requires every functional argument to have
a user-visible name. At a call containing an inline lambda, the compiler first
derives that lambda's combined HM/effect judgment. It transfers the solved type,
latent scheme, completeness, and returned-arrow stages to a generated lexical
binding in a temporary child inference environment. The existing fused named
application rule then checks and specializes the call unchanged.

This bridge preserves the crucial phase distinction: evaluating a lambda value
is pure, while invoking it realizes its latent body effects. The regression
passes =lambda x -> ioFn x= directly to =applyHigherInline= and requires a
recursively fused, complete, closed row with exactly one =io=. Its negative
companion passes =lambda x -> openNetwork x= and requires the known =network=
label together with an open row and incomplete evidence.

The elaborator restores every original AST argument pointer after inference;
generated names and their reference-counted schemes live only in a temporary
child environment. Thus this is a type/effect elaboration device, not a source
or runtime rewrite.

The supported expression-valued fragment is presently immediate lambda
arguments. Conditionals returning closures, closures stored in aggregates,
capturing inline lambdas whose environments affect QTT ownership, and portable
module serialization still require a general value-level callable contract in
the compiler IR.

* Cycle 110: one owned callable-contract transport

The effect scheme and its arrow stages no longer have to travel as five
unrelated parameters between compiler phases. =InferCallableContract= owns the
saturated scheme and completeness bit together with the ordered stage schemes
and their completeness vector. It can retain evidence from a combined
expression judgment or an installed =TypeScheme=, survive destruction of the
producer, and be installed into another scheme through one checked operation.

Inline-lambda elaboration and =env_hm_infer_define= now consume this shared
transport instead of duplicating field-by-field ownership logic. The sanitizer
regression extracts a returned-arrow contract, frees its source judgment,
instantiates the retained stage afterward, installs it into a new scheme, and
round-trips it back to a second owned contract.

Callable-contract fingerprinting is centralized. It covers the saturated
effect scheme, saturated completeness, every ordered stage fingerprint, and
every stage completeness bit. Changing only proof completeness now changes
identity; previously the saturated completeness bit was accidentally absent.

This is the correct in-memory authority for a future interface manifest, but
not the manifest itself. The next serialization cycle should encode this one
object, including a version and canonical effect-row representation, instead of
inventing a separate module-only effect model.

* Cycle 111: versioned callable contracts cross a byte boundary

The first canonical effect interface format now exists. A
=monad-effect-scheme-v1= payload records the semantic fingerprint, open/closed
tail, canonical hex-encoded labels, and ordered callable =(domain, depth)=
dependencies. Deserialization reconstructs a fresh arena-owned scheme and
publishes it only if the recomputed fingerprint equals the declaration.

The enclosing =monad-callable-contract-v1= format contains the saturated
scheme and completeness bit followed by every ordered arrow-stage scheme and
stage completeness bit. Nested scheme payloads are hex encoded, so the two
versioned grammars remain independently parseable. The contract decoder builds
an owned temporary value, verifies its complete semantic fingerprint, and only
then replaces the caller's destination.

Sanitizer regressions round-trip an open residual scheme with callable domain
three at invocation depth two, and a full returned-arrow callable contract that
survives its original judgment. Both regressions mutate the final encoded byte
and require deserialization to fail rather than accept corrupted evidence.

Version 1 intentionally supports structural label rows only. Typed atoms carry
generative capability and type identities, operation names, scope, and exact
QTT resumption quantities. Until all of those fields have one canonical
encoding, their serializer fails closed. The next cycle should extend the
scheme grammar for typed atoms and then attach the verified contract payload to
the existing module interface rather than creating a parallel manifest.

* Cycle 112: effect authority survives module boundaries

Typed effect atoms now have a canonical =monad-effect-scheme-v2= encoding. The
format preserves kind, constructor/type/capability identities, exact
resumption quantity, scopedness, and nullable name and operation fields. The
reader remains backward compatible with label-only =v1= payloads, recomputes
the complete semantic fingerprint, and rejects corruption before publishing a
scheme.

The existing quantitative module interface is now version 2 and carries the
same =InferCallableContract= payload rather than a second effect model. Each
record stores the contract's semantic fingerprint and an independent checksum
of its encoded bytes. Provider inference registers the contract alongside the
ownership signature; interface emission writes both. Consumer imports verify
the interface, decode the callable contract, compare its semantic fingerprint,
and install it into the HM environment under both qualified and permitted
unqualified names.

The production regression compiles a provider and consumer, observes the
verified effect-contract installation, checks the emitted =.mqti= payload,
inspects caller LLVM reclamation, and executes the linked program. Version 1
ownership-only interfaces remain readable. The remaining interface gap is
structural/polymorphic HM type serialization: effect transport is real for
exports whose ownership signature fits the current closed flat ABI fragment.

* Cycle 113: structural HM types enter the interface

=.mqti= version 3 replaces compilation-local integer type tags with a canonical
recursive type grammar. Child types are explicitly delimited and every
constructor carries precisely the data used by =qtt_type_fingerprint= and
structural equality. The first complete family includes primitive types, HM
variables and arrows, lists, maps, arrays and their representation flags,
optionals, pointers, abstract collections, variadics, arbitrary-width integers,
legacy function descriptors, named type applications, finite named types, and
structural layouts including field names, offsets, sizes, alignment, packing,
scalar/inline flags, and nested field types.

Interface ownership now deep-copies and destroys this graph through the same
codec boundary. The reader enforces recursion and collection bounds, exact
delimiters, enum domains, boolean domains, and whole-input consumption before
the existing signature fingerprint can authorize a contract. Interface v1 and
v2 remain readable with their flat type tags; ambiguous reinterpretation was
avoided by assigning the structural grammar a new interface version.

The regression round-trips an arrow whose variable occurs inside a named type
application nested in a map, together with a structural layout result whose
field contains an optional. It then verifies the reconstructed graph and the
stable signature fingerprint. Production provider/consumer tests continue to
verify imported effect evidence, LLVM reclamation, and execution under v3.

This is structural transport, not yet full HM scheme transport: quantified
variable sets, class constraints, higher-kinded binders, recursive graph
backreferences, and nominal ABI identity beyond the encoded layout description
remain explicit future boundaries.

* Cycle 114: alpha-canonical HM scheme contracts

=monad-hm-scheme-v1= now serializes a quantified HM scheme independently of
compilation-local variable allocation. Quantified variables are renamed to
dense canonical indices in binder order before the structural type codec and
fingerprint run. Thus =forall a. a -> a= and =forall z. z -> z= have identical
bytes, while =forall a b. a -> b= remains distinct. Duplicate binders,
unquantified free variables, unknown types, malformed counts, corrupted bodies,
and non-canonical decoded variables fail closed.

Decoded schemes explicitly own their type graphs. =TypeScheme= now records
that ownership, so cloning performs a deep type clone and destruction releases
the graph without changing the historical shared-type behavior of ordinary
inference schemes.

=.mqti= version 4 carries the canonical HM payload with its own byte checksum.
Type/effect metadata is no longer conditional on an ownership proof: a metadata-
only export record can carry an HM scheme while correctly declaring that no
reclamation signature exists. Consumer installation prefers the decoded
polymorphic scheme and then attaches the independently verified callable-effect
contract; old interfaces and exports without HM evidence retain the
monomorphic ABI fallback.

Sanitizer tests establish alpha-equivalence, sharing sensitivity, round-trip
ownership, numeric-overflow rejection, and tamper rejection. Interface tests
establish metadata-only round-trip independently of ownership evidence.
Concrete provider/consumer compilation continues to exercise v4 HM, effect,
ownership, LLVM, and runtime transport.

The production generic-export seam is now covered as well. Interface emission
falls back to metadata-only HM evidence when an open polymorphic ownership
signature is outside the closed ABI grammar; it no longer drops the whole
export. Recursive let generalisation computes =ftv(A) ∖ ftv(Γ ∖ x)=, excluding
the provisional self binding rather than accidentally monomorphising an unused
definition. The compiler also restores and uses the current source identity at
the HM/QTT and interface boundaries instead of trusting reader-global state
left by dependency work. An end-to-end regression exports =forall a. a -> a=,
imports it into another module, instantiates it independently at =Int= and
=String=, links, and executes both calls.

This does not yet transport type-class predicates, kinds, higher-rank
quantifiers, or polymorphic ownership proofs. Those remain distinct extensions
to the interface judgment rather than hidden claims of this cycle.

* Cycle 115: checked kind algebra for qualified polymorphism

Qualified schemes now have an executable kind-theoretic foundation in
=qtt/kind.[ch]=. Kinds are freely generated by:

#+begin_src text
κ ::= Type | EffectRow | κ → κ | α
#+end_src

The solver implements metavariable resolution, structural arrow unification,
an occurs check forbidding =α ≐ κ → α=, and transactional failure. If any
component of a structural constraint fails, bindings made while checking its
earlier components are rolled back; a rejected constraint therefore cannot
silently bias later inference. Closed solved kinds have a canonical
=monad-kind-v1= representation and stable semantic fingerprint. Open
metavariables are deliberately not serializable.

The sanitizer regression checks successful higher-kinded unification, effect-
row distinction, occurs rejection, rollback after a partially successful arrow
constraint, canonical round-trip, fingerprint agreement, and malformed-input
rejection. Both build systems compile the implementation.

This cycle does not yet claim kind inference for all surface type constructors.
The next integration boundary is to associate a checked kind with every HM
quantifier and class constructor, then admit a predicate =C τ= only after
=C : κ → Constraint= and =τ : κ= have unified. Only that checked predicate may
enter the next qualified-scheme interface format.

* Cycle 116: source-free effect replay and graded handler admission

The separately compiled callable fragment no longer requires provider source.
Given object =O= and interface =I=, import replay checks the judgment

#+begin_example
parse(I)    module(I) = requested    artifact(I) = fingerprint(O)
─────────────────────────────────────────────────────────────────
                    O ; I is admissible
#+end_example

and reconstructs only exports whose interface records carry complete ABI and
ownership signatures. HM-v2 predicates and callable-contract-v2 evidence then
enter the ordinary imported environment. The end-to-end regression removes
the provider source, compiles, links, and executes a consumer; mutations of
either predicate bytes or object bytes are rejected before linking. Layouts,
macros, typeclasses, reader transformers, and FFI headers remain outside this
certified fragment rather than being guessed from legacy metadata.

The effect kernel also admits handler subtraction only after replaying the QTT
resumption premise =q*u <= a=. Here =q= is the operation's Core-declared
resumption grade, =u= is continuation demand per invocation, and =a= is the
captured resource allowance. Success removes exactly one structural effect
atom, including its generative capability identity. Sanitizer coverage checks
abortive, linear, unrestricted, rejected, and absent-handler cases. Core now
publishes representative =omega= and scoped declarations, while surface
handler syntax, evidence passing, and selective-CPS lowering remain the next
vertical slice.

* Cycle 117: coherent handler sets and Core-owned profiles

The single-operation admission premise now lifts to a transactional handler
set. Exact structural atoms—including generative capability identity—must be
pairwise distinct. Every clause proves its quantitative continuation premise,
then the handled multiset is subtracted and clause-body effects join the
residual computation row. A scoped capability occurring in its own clause
effect is rejected as an escape. Failed sets publish no residual or output
authority.

The evidence fingerprint covers each atom, continuation/capture quantities,
clause effects, residual row, and output row. Clause witnesses are sorted
before hashing, so permuting source clauses cannot change proof identity. The
verifier reconstructs the judgment and rejects altered fingerprints.
ASan/UBSan tests exercise success, permutation, duplicate incoherence, scoped
escape, and proof replay.

Core also owns handler policy names through =effect-handler=. Profiles resolve
an existing effect declaration and statically prove that their continuation
usage is bounded by the operation resumption quantity. Core publishes abortive
exception, one-resumption yield, and scoped-local profiles. This is the
certified front half of source handlers; clause ASTs, operation dispatch,
evidence passing, and direct/CPS lowering remain deliberately unclaimed.

* Cycle 118: handler authority survives separate compilation

=.mqti= version 8 adds a canonical =HANDLERS= section. Each profile carries
its Core-owned name, referenced effect declaration, continuation quantity, and
deep/shallow policy. Profiles are sorted by name and protected by a section
fingerprint. Reading is dependency ordered: effect declarations are verified
first, then every profile replays =usage <= resumption(effect)=. Unknown
effects, altered quantities, duplicate conflicts, and fingerprint changes are
rejected.

The ordinary compiler registers source profiles with the module evidence
producer; source-free imports reconstruct declarations and profiles from the
same interface before installing callable contracts. The regression builds a
provider containing an effect and profile, removes its source, compiles and
executes a consumer, and retains the existing interface/object tamper checks.

Transactional handler evidence now serializes as
=monad-handler-proof-v2|n|proof|residual|output=. Its verifier re-elaborates the
complete handler set and compares clause count plus all three semantic
fingerprints. Changing even the output-row field is rejected. This provides a
portable checked boundary for future typed-Core handler nodes without claiming
runtime dispatch or CPS lowering prematurely.

* Cycle 119: computations become first-class typed Core

=perform= and =handle= no longer collapse into ordinary application at the
semantic boundary. Typed Core has dedicated nodes carrying the declared
effect/profile name, children, and a stable nonzero capability identity. The
identity is derived from module identity, form, name, and source position, so
it is reproducible within a compilation unit but cannot alias across modules.

Validation, capture discovery, resource usage, closure liveness, semantic
write discovery, demand fingerprints, and result-origin analysis now traverse
the new nodes explicitly. A perform consumes the resources of its argument; a
handle sequences computation construction with clause construction. Demand
certificates commit to names, identities, and children, while handler results
remain origin-unknown because dynamic authority may select either path.

This cycle establishes the computation calculus boundary; it intentionally
does not claim executable operation dispatch. The next slice must resolve
names against Core declarations/profiles during elaboration, attach the
portable handler proof to =QTT_CORE_HANDLE=, and lower verified abortive and
one-shot profiles through direct/selective CPS paths. Multi-shot lowering must
remain rejected until continuation cloning has resource semantics.

* Cycle 120: certified operation introduction and elimination

The computation calculus now has an independent effect-elaboration pass.
=perform E v= resolves =E= against the open Core declaration registry, copies
its constructor, traits, scope, operation, and resumption quantity into an
exact structural atom, and extends the effects of =v=. Ordinary source-effect
inference also recognizes =perform= directly, so it no longer reports the form
as an unknown callee or accidentally loses its latent effect.

=handle H c h= resolves =H= against the Core-owned profile registry and, for
the initial exact-operation slice, reconstructs the generative atom introduced
by =c=. It applies the transactional handler judgment

#+begin_example
q * u <= a       effects(c) = {E#cap} + epsilon
------------------------------------------------
handle H c h : epsilon join effects(h)
#+end_example

and attaches =monad-handler-proof-v2= only after success. The verifier retains
the computation row, clause row, exact atom, continuation use, and capture
allowance and semantically replays the judgment. Proof mutation, unknown
declarations/profiles, profile mismatch, absence, grade failure, scoped escape,
and shallow profiles fail closed.
Re-elaboration consumes any previously attached witness before checking, so a
failed weaker-authority recheck cannot leave stale executable evidence behind.

Backend policy is now explicit: abortive authority admits direct lowering,
one-shot authority admits a future linear-continuation path, and finite
multi-shot or unrestricted authority remains unsupported. Static proof is not
confused with executable implementation. Demand and authority fingerprints
commit to resolved constructor metadata, resumption class, scope, depth, and
portable proof bytes. Core publishes =Core.IO.read-once= as the first ordinary
I/O handler profile intended for the coming end-to-end runtime slice.

* Cycle 121: proof-gated abortive dispatch

The first handler policy is now executable below typed Core. A backend plan is
issued only for a deep, certified =QTT_CORE_HANDLE= whose exact operation has
resumption quantity zero. Certification semantically replays the attached
handler proof and records constructor identity, generative capability,
authority fingerprint, proof fingerprint, operation, and clause. Consumption
re-certifies all of those fields; a copied or mutated plan is not authority.

The runtime ABI is explicit-state and reentrant. A =QttEffectRuntime= owns a
strict LIFO chain of caller-owned frames. Dispatch searches from the innermost
frame for exact equality of =(constructor, capability)=. A nearer frame for a
different capability cannot intercept the operation; an absent frame produces
an explicit unhandled result. Push rejects zero identities, null clauses, and
already-active frames, while pop rejects non-LIFO removal.

For an accepted abortive plan the backend installs one frame, dispatches the
operation to the clause, and restores the frame before returning the handler
result. The same proof is checked at plan issuance and consumption. One-shot,
finite multi-shot, unrestricted, shallow, missing-proof, and altered-proof
nodes are rejected by this path. Semantic IR now preserves the operation's
constructor and capability fields and its verifier rejects forged authority.

This is executable algebraic dispatch, but not yet surface LLVM lowering:
source =perform=/=handle= still needs clause ABI typing and code-generation
integration. The next slice should map typed clause arguments/results onto the
runtime frame ABI, emit exceptional cleanup edges, and then introduce an
affine one-shot continuation object as a separate backend policy.

* Cycle 122: first source-to-executable handler

Monad source now recognizes =perform E payload= and
=handle H computation clause= as typed special forms. The first surface ABI is
intentionally homogeneous: if the payload has type =T=, the operation and
handler result have type =T= and the clause must have type =T -> T=. This is a
temporary sound restriction, not an inference guess; general =P -> R=
operations require Core declarations to transport operation signatures.

Code generation lowers only the exact form
=handle H (perform E payload) clause=. It constructs typed Core using the
compilation module identity, elaborates the structural effect with capture
allowance zero, replays the portable handler proof through the abortive backend
certifier, and only then applies the =q=0 reduction to =clause(payload)=. A raw
=perform= is rejected as unhandled. One-shot and multi-shot profiles are
rejected with a targeted diagnostic rather than routed through the direct
path.

=how_to/AbortiveEffects.mon= is the first real user-facing executable example.
The regression invokes the public compiler, emits a native program, executes
its tests, checks unhandled-operation diagnostics, checks clause type mismatch,
and checks one-shot rejection. Thus the entire path is now source → HM typing →
typed Core → quantitative proof → backend certificate → LLVM → native code.

The direct reduction is valid specifically because =q=0: there is no captured
continuation and therefore no exceptional cleanup edge in this restricted
expression. The next generalization must add typed operation signatures to
Core/interface declarations, followed by nonlocal abortive control and cleanup
for operations nested inside arbitrary computations.
