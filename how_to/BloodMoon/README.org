#+TITLE: Blood Moon
#+STARTUP: showeverything

Blood Moon is the Vulkan-first foundation for a bullet-heaven game written in
Monad.  Monad will own game state, collections, resource lifetimes, scheduling,
and shader artifacts.  GLFW and Vulkan are foreign boundaries, not a hidden C
engine.

* The first vertical slice

=Shaders.mon= contains the complete vertex and fragment programs as typed,
contiguous =[N U32]= buffers.  Vulkan consumes SPIR-V as 32-bit words, so this is the
native boundary: no file loading, C allocation, or pointer-sized byte guessing
belongs in the renderer.

The vertex stage draws one fullscreen triangle without a vertex buffer.  The
fragment stage builds an animated arterial-red sigil from signed-distance
geometry, a breathing halo, blood grain, and a dark radial falloff.  This keeps
the first GPU pipeline tiny while giving the project a visual identity.

Editable shader sources remain in =shaders/=.  The regression test recompiles
and validates them, then requires every embedded word to match:

#+begin_src sh
pytest -q tests/test_blood_moon_shaders.py
#+end_src

* Ownership rule

The renderer must not call =malloc=, =calloc=, or =free=.  Fixed Vulkan tables
use Monad's contiguous arrays; long-lived dynamic game data will use Core
buffers with explicit ownership and effects.  Vulkan allocation functions are
allowed because they allocate Vulkan resources owned by Vulkan handles, not
host-language bookkeeping.

* Next vertical slice

=core/Graphics/Vulkan= now owns checked shader-module creation and destruction;
=BloodMoon.mon= supplies only its embedded words.  Extend that Core boundary
with linear, scope-owned instance, device, swapchain, pipeline, frame
synchronization, resize, and teardown, then present the fullscreen shader
through a GLFW surface.  The tutorial entry point should only describe the
scene and run it.
